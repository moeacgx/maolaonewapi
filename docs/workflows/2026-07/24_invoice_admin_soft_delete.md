# 发票管理单条与批量删除

## 变更目标

发票管理页原先仅支持查询和状态处理，管理员无法清理误创建或无需继续展示的记录。本次补充单条删除与批量删除能力，并保留财务审计所需的原始数据。

## 方案与接口

- `DELETE /api/user/invoice/:id`：管理员软删除一条发票记录。
- `POST /api/user/invoice/batch`：管理员批量软删除发票记录，请求体为 `{"ids":[1,2]}`，单次最多 100 条。
- 两个接口沿用 `/api/user` 管理路由的管理员鉴权。
- 删除使用 GORM 软删除；默认发票列表不再返回已删除记录，但数据库仍保留原记录、来源订单关联和开票状态，防止已开票订单被再次申请。
- 未支付且仍处于 `payment_pending` 的合并开票申请会先执行原有取消流程，释放来源订单，再软删除申请记录。
- 重复 ID 会归一化；不存在或已删除的 ID 不计入成功数量。

## 数据与兼容性

- `invoice_records` 新增可空的 `deleted_at` 字段和索引，由现有 AutoMigrate 在 SQLite、MySQL、PostgreSQL 上创建。
- 直接来源发票的幂等检查包含软删除记录，避免支付回调因唯一索引冲突而失败。
- 已支付或已开具发票删除后不回退来源订单的 `invoice_required` 和 `invoice_status`，从而避免重复开票。

## 测试计划

- 验证单条和批量删除只隐藏指定记录并返回实际删除数量。
- 验证重复、无效、不存在的 ID 的归一化与边界限制。
- 验证已开具记录保留来源订单开票状态。
- 验证未支付合并申请删除时释放订单及关联记录。
- 执行发票相关 Go 单元测试，最大超时 60 秒，并执行 `git diff --check`。
