# 充值余额与订阅套餐用途提示验证记录

## 变更目标

余额购买订阅关闭时，在充值页面明确区分余额充值和订阅套餐购买，避免用户误以为充值余额可直接用于购买订阅套餐：

- 充值余额仅用于 API 调用消耗，不可用于购买订阅套餐。
- 订阅套餐请在「订阅套餐」页面单独购买。

## 变更范围

- Default 充值页：`/wallet`。
- Classic 充值页：`/console/topup`。
- 两套前端的简体中文及现有多语言翻译资源。

本次仅调整页面提示文案，不改变充值、余额扣费、订阅购买、支付方式、权限或后端接口行为。

## 展示与交互约定

- 仅当 `/api/user/topup/info` 的 `enable_balance_subscription` 明确为 `false` 时展示提示；值为 `true`、尚未加载或字段缺失时隐藏。
- 提示显示时应在充值卡片内清晰可见，并与充值金额、支付方式等操作区保持合理层级。
- 本次按文案范围只展示文字提示，不新增或变更导航链接。
- 文案必须通过现有 i18n 机制渲染，不得在组件中绕过翻译函数写死非基础语言文本。
- 提示在桌面端、移动端和深色模式下均应保持可读。

## 兼容性与安全边界

- 不新增或修改 API、数据表、配置项及权限判断。
- 不改变现有充值和订阅购买入口的可用条件，只让提示与余额购买订阅的有效开关状态一致。
- 不涉及数据库迁移或回滚；回滚时移除对应页面提示和翻译键即可。

## 验证结果

- Default TypeScript 类型检查通过。
- Default 组件、Classic 组件及两份工作文档的 Prettier 检查通过。
- Classic 目标组件 ESLint 检查通过。
- Default i18n 同步完成，六种语言均无缺失键或额外键；本次两个新键在两套前端共 14 个语言文件中均存在且非空。
- 目标文件 `git diff --check` 与开发文档链接检查通过。
- Default ESLint 未能执行：现有依赖中的 `brace-expansion` 与 ESLint 期望接口不匹配，启动阶段即报错，未进入代码检查。
- 本次未启动固定本地服务进行页面手工验证；改动不涉及接口或业务逻辑，仍建议合并前在窄屏、深色模式及中英文界面下复核提示布局。

## 已知限制

- 本提示用于说明产品规则，不替代后端对充值、余额消费或订阅购买的权限校验。
- 提示跟随余额购买订阅有效开关自动显示或隐藏，无需部署方手工同步文案。
- 当前普通用户套餐购买组件仍嵌在充值页；现有独立 `/subscriptions` 路由用于管理员套餐管理，并非普通用户购买页。
