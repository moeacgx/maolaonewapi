# 开发反思报告：安全审计关键词边界与流式处理

**日期**：2026-07-31

**提交类型**：bugfix

**范围**：安全审计关键词匹配、事件动作筛选、SSE 流式响应、Default/Classic 管理页面

## 1. 概述

本次修复了英文关键词按连续子串匹配导致的误命中，并补齐了事件处理结果展示和筛选。
审查过程中进一步发现，SSE 分片独立扫描会在关键词跨分片时误拦截或漏掉 mask，因而
增加了带左右边界确认的流式缓冲和结束刷新逻辑。

## 2. 遇到的问题

### 问题 1：英文短语误进入规则

`Master Key` 会命中 `Webmaster Keyword` 的内部片段。根因是后端、前端高亮和脱敏均只
执行忽略大小写的连续子串搜索，没有统一的 ASCII 词边界。

### 问题 2：流式右边界提前确认

在 `Master Key` 恰好位于当前分片末尾时，下一片可能继续以英文字符开头，前一片不能
立即视为命中。跨分片扫描若在此处直接接受候选，会误拦截 `Master Key` + `word`。

### 问题 3：跨分片 mask 绕过

`Master Ke` 与 `y` 分属不同分片时，逐片 mask 都看不到完整关键词，原文可能直接发送给
客户端。

### 问题 4：删除确认条件不完整

动作筛选在模型层没有统一规范化，空白动作可能形成无条件删除保护之外的异常条件；原有
测试的插入顺序也不足以证明删除阶段仍绑定动作筛选。

## 3. 解决方案

- 关键词首尾为 ASCII 字母、数字或下划线时，要求相邻字符不是同类 ASCII 字符；中文
  关键词继续使用连续子串语义。
- Default 与 Classic 高亮复用同样的边界规则。
- SSE 只暂存可能继续组成关键词的尾部分片；ASCII 关键词等待下一字符或流结束确认
  右边界。流结束先 flush block/mask，再发送 `[DONE]`。
- 跨分片 mask 按原 JSON 文本字段的字符范围重写，替换串写入命中起始字段，后续字段
  删除命中剩余字符，并保留每个 SSE 分片原有事件类型和顺序。
- 动作筛选统一执行 `Trim + ToLower`，列表、删除预览和确认删除使用同一条件；删除测
  试反转记录顺序并断言其他动作记录仍保留。

## 4. 调试过程

1. 通过后端、Default、Classic 三套边界测试确认普通文本误命中来源。
2. 复核流式调用链，定位当前分片扫描先于跨分片检查、发送前缓冲未实际接入的问题。
3. 增加 `Web` + `Master Key`、`Master Key` + `word`、`Master Ke` + `y` 三类分片
   场景，先修正右边界延迟语义，再实现跨分片 mask 改写。
4. 增加 SSE 真实发送路径测试，验证 block 不泄漏暂存内容、mask 不保留原文、事件标签
   不错位。
5. 运行格式化、Go 测试、`go vet`、Node 测试、TypeScript 检查和两套生产构建。

## 5. 经验总结

- 流式敏感词检测必须区分“当前已命中”和“当前只能暂存等待更多上下文”，不能把分片
  边界当成文本边界。
- Block 与 Mask 必须共享同一匹配器和边界语义，否则展示结果会与实际处理不一致。
- 处理跨分片替换时，除了文本内容，还必须保留协议事件类型和输出顺序。
- 删除确认测试需要主动构造“同一高水位内的其他动作记录”，才能证明筛选条件没有在
  删除阶段丢失。
