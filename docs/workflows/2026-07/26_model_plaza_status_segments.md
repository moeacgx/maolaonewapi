# 模型广场四段式状态条

日期：2026-07-26

## 变更目标

- 将模型性能详情中逐桶展示的密集状态条压缩为固定四段，降低视觉噪声。
- 在模型广场卡片中展示相同的四段式状态条，不再使用装饰性的灰色占位条。
- 两处展示复用同一段落计算和颜色阈值，避免成功率口径与样式漂移。

## 范围与数据契约

- 同步调整 Default 与 Classic 前端的模型广场和模型详情性能区。
- 继续使用 `GET /api/perf-metrics/summary?hours=24` 与
  `GET /api/perf-metrics?model=<name>&hours=24`，不新增接口或数据库字段。
- 摘要接口的 `data.models[].series[].status_rate` 作为模型卡片状态条数据源；
  它取同一模型、同一时间桶内最佳可用分组的成功率。原有 `success_rate` 继续保留
  全部分组、全部请求的真实汇总口径，详情页和其他统计不受影响。
- 四段按最近 24 小时等分，每段覆盖 6 小时，顺序为从旧到新。段内存在多个
  指标桶时取桶成功率平均值；没有请求样本的时段显示为中性色，不推断为成功或失败。
- 模型广场的可用状态颜色使用主题语义色：最佳分组 `>= 95%` 为可用，`> 0%`
  但低于 `95%` 为降级，所有分组均为 `0%` 才显示异常；无数据使用弱化中性色。
  详情页的真实成功率仍使用原有成功率阈值，不改变监控口径。

## 交互与兼容性

- 每一段均可悬停查看时间范围和该段状态率；模型卡片不再展示时间戳和整体百分比，
  仅保留四段状态，避免把质量百分比误读为整个模型不可用。详情页仍保留完整数据。
- 卡片底部把延迟、吞吐量、状态组织成右对齐三列，计费类型保留在左侧；窄屏下
  三列摘要独占一行。
- 摘要接口继续返回 `series`，新增的 `status_rate` 为可选字段，旧前端忽略后仍保持兼容。
- 当性能统计未开启或模型没有样本时，卡片不显示性能摘要；部分时段无样本时仅将
  对应段标为无数据。

## 安全边界

- 页面只消费现有公开模型性能摘要，不增加用户、令牌、渠道密钥或请求明细字段。
- 状态条不展示请求量，避免通过卡片批量接口扩大流量明细暴露范围。

## 测试计划

- 单元测试覆盖 24 小时四等分、无数据段、边界时间点、非法样本过滤和段数限制。
- 执行 Default 前端类型检查、Default 与 Classic 相关 Node 单元测试、两套前端
  的 Prettier 检查以及 `git diff --check`。
- 手工核对两套前端的桌面与窄屏模型卡片，确认四段状态条、成功率数字和悬停提示
  不挤压卡片。

## 验证结果

- Default 四段计算单元测试 `4/4` 通过，Classic 性能工具测试 `6/6` 通过。
- Default TypeScript 类型检查、Default 生产构建、Classic 生产构建均通过。
- Classic 修改文件 ESLint 通过；Default ESLint 仍在启动阶段受工作区既有
  `brace_expansion_1.expand is not a function` 依赖错误阻塞，与本次代码无关。
- 两套前端相关文件 Prettier 检查与仓库 `git diff --check` 通过；差异检查仅提示
  工作区既有的换行符转换警告。
- 固定本地环境 `3000/3001` 的状态接口、Classic 首页、默认账号登录和演示数据
  接口验证通过，验证后已停止测试进程。
- 使用安全的浏览器请求拦截提供两组仅供展示的模型性能样本，在 `1440x900` 与
  `390x844` 视口确认 Classic 模型卡片均为四段状态条；窄屏页面
  `scrollWidth === clientWidth`，未出现横向溢出或内容遮挡。
- Default 模型广场沿用相同的已测试四段计算，并通过类型检查与生产构建；当前固定
  本地手工测试入口只运行 Classic，因此未另开非规范端口做 Default 页面截图。
