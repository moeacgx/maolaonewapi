# 安全审计上下文方向标签与筛选

## 问题

审计详情此前只渲染一段完整提示词，没有明确说明记录对应客户端请求还是 LLM 返回，
长正文的滚动范围也不够直观，审核员难以快速定位查看方向。

## 修改范围

- Default 与 Classic 详情在每段完整上下文旁显示来源标签：`客户端输出` 或
  `LLM 输出`，同时保留对应的 `user`、`assistant` 等原始角色。
- 增加 `全部输出`、`客户端输出`、`LLM 输出` 三个可点击标签，默认选中全部输出，
  筛选会真正过滤上下文段落而不是只根据事件阶段显示提示。
- 后端从请求协议提取消息角色并随审计事件保存，系统、开发者和工具结果归为客户端
  上下文，assistant/model 归为 LLM 上下文。旧事件没有角色数据时继续渲染完整正文。
- 正文区域设置独立的最小高度、最大高度和纵向滚动，长上下文不会撑开详情弹窗。

## 兼容性说明

三项标签不改变审计正文或哈希；角色元数据与正文一同进入 AES-GCM 密文保存，数据库
不会明文保存上下文段落。未配置稳定密钥时沿用 Root-only 明文兼容前缀。旧版本事件
直接保存 JSON 数组时仍可读取，事件不含段落索引时自动回退为单段全文显示。

## 验证

- 打开同时包含历史消息和用户输入的事件，默认显示全部内容，并可分别切换客户端或
  LLM 输出，确认每段都有清晰标签。
- 在长正文中确认内容区域可以独立上下滚动。
- 执行 Default 类型检查、Classic 安全审计测试及两套生产构建。
