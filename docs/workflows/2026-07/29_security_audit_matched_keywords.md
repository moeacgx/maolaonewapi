# 安全审计命中词详情契约

## 问题

屏蔽词事件此前只保存命中规则标识，Root 审核员无法直接确认一条规则实际命中了哪个
关键词。

## 方案

- 屏蔽词事件从 `SensitiveFilterMatch.Keyword` 提取非空关键词，按首次出现顺序去重。
- 命中词保存到事件的敏感元数据列，不进入基础事件分页查询或模型 JSON；Root 列表接口
  在分页后按当前页事件 ID 单独批量读取并解密为 `matched_keywords`。
- 配置稳定 `CRYPTO_SECRET` 时使用 AES-GCM 密文；未配置时沿用 Root-only 明文兼容
  模式，并使用显式版本前缀。
- 详情接口返回 `matched_keywords: string[]`；非屏蔽词事件和升级前的历史事件返回
  空数组。
- Default 与 Classic 详情都把命中词显示为红色标签，并在完整正文及所有上下文分段的
  Markdown 文本节点中做大小写不敏感的字面高亮；原有链接、列表、代码块等 Markdown
  结构保持不变。空词、重复词和重叠命中范围会先规范化，避免重复标签或破坏正文。

## 兼容性与安全边界

新增字段由 GORM 自动迁移，使用跨 SQLite、MySQL 和 PostgreSQL 的 `TEXT` 类型；
旧行读取为空字符串。列表查询不选择敏感元数据列，避免普通列表响应或调试序列化意外泄露
命中词。详情接口继续受 Root 权限和 `no-store` 响应保护。

## 验证

- 有稳定密钥时数据库列不包含关键词明文，详情可恢复去重后的关键词列表。
- 无稳定密钥时使用显式兼容前缀，详情仍可返回关键词。
- 基础列表模型不读取敏感元数据，内部密文字段不序列化；Root 列表响应只返回解密后的
  `matched_keywords`。
- 历史事件详情返回非空的空数组，而不是 `null`。
- Default 的高亮分段测试与 TypeScript 检查、Classic 的高亮插件测试与生产构建均通过。
