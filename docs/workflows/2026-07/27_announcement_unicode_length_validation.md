# 公告 Unicode 字符长度校验修复

## 问题

系统公告编辑器将正文限制描述为最多 500 个字符，但后端使用 Go 字符串字节长度校验。
中文通常占用三个 UTF-8 字节，导致不满 500 个字符的公告仍可能被拒绝，并提示
“第 N 个公告的内容长度不能超过 500 字符”。公告说明字段也有相同问题。

## 根因

`validateAnnouncements` 使用 `len` 统计正文和说明。`len` 返回 UTF-8 字节数，
与前端向用户表达的字符数语义不一致。

## 修改范围

- 公告正文改为按 Unicode 码点统计，最多 500 个字符。
- 公告说明改为按 Unicode 码点统计，最多 200 个字符。
- ASCII 内容的既有边界保持不变，不改变公告 JSON 结构、接口和存储格式。

## 兼容性与安全边界

- 不涉及数据库迁移，SQLite、MySQL 和 PostgreSQL 行为一致。
- 只放宽此前被字节计数误拒绝的多字节文本，不放宽声明的字符数量上限。
- 空内容、发布日期、公告类型和公告数量等既有校验保持不变。

## 验证结果

- 单元测试确认 500 个中文字符的正文通过，501 个被拒绝。
- 单元测试确认 200 个中文字符的说明通过，201 个被拒绝。
- `go test ./setting/...` 通过。
- `git diff --check` 通过。
