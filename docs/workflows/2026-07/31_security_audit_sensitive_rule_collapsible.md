# 安全审计屏蔽词规则默认收起

## 目标

安全审计的屏蔽词规则数量较多时，全部规则同时展开会显著拉长页面并增加渲染节点。
本次调整 Default 与 Classic 两套管理页，使已保存规则默认收起，同时保留快速识别和
编辑单条规则的能力。

## 变更范围

- 有效的已保存规则首次加载后全部默认收起，不持久化展开状态。
- 新增规则自动展开，管理员可直接填写内容。
- 每条规则独立展开或收起；标题展示规则名称、启用状态、动作和检查范围摘要。
- 启用规则缺少指定渠道或指定分组时首次自动展开并显示错误；之后仍允许手动收起，
  标题持续保留错误标识，修正目标也不会导致正在编辑的规则突然收起。
- 开关和删除按钮与折叠触发器分离，不会误触展开状态。
- 折叠触发器使用原生按钮和 `aria-expanded`、`aria-controls`，支持键盘操作。
- 不加入循环动画；收起时不渲染正文编辑控件，以降低规则较多时的页面节点数量。

## 数据与兼容性

折叠状态仅保存在当前 React 组件内，不写入 `SensitiveRules` 或其他 Option。接口、规则
JSON、数据库结构、请求过滤行为和权限边界均不改变。Default 与 Classic 继续复用同一
屏蔽词配置及校验规则。

## 测试计划

- 检查两套前端的有效规则默认收起、新增规则自动展开及重置恢复初始状态。
- 检查每条规则独立控制，并确认开关和删除按钮不嵌套在折叠触发器中。
- 检查无有效目标的启用规则首次自动展开、可手动收起、标题错误可见，并在修正目标后
  保持当前展开状态。
- 执行双前端专项测试、格式化、类型或静态检查、生产构建及固定本地环境验证。

## 验证结果

- Default 安全审计与折叠状态专项测试通过，24 项全部成功。
- Classic 屏蔽词、折叠状态与安全审计专项测试通过，9 项全部成功。
- Default TypeScript 类型检查和生产构建通过。
- Classic 目标 ESLint 和生产构建通过；构建只有仓库既有的大分块、Browserslist 与
  `lottie-web` 警告。
- 两套前端目标文件 Prettier 检查和 `git diff --check` 通过。
- 固定本地环境验证通过：`/api/status`、Classic 首页、Root/Demo 默认账号及演示数据
  接口均正常。
- Default ESLint 仍被本地既有的 `brace-expansion`/`minimatch` 依赖错误阻断，尚未进入
  目标文件检查；类型检查、专项测试和生产构建已覆盖本次 TypeScript 变更。
