# classic 后台导航静态化回归修复

## 背景

生产环境从 `v1.0.0-rc.10.1.10.199` 升级到后续版本后，classic 后台出现点击侧栏、顶栏后页面不切换的问题。用户手动刷新目标地址后页面可以进入，说明服务端路由和页面资源仍可用，问题集中在前端单页应用的导航交互链路。

## 根因

`v1.0.0-rc.10.1.10.206` 为修复侧栏导航时，将侧栏内部导航从 `Link` 包装改为只依赖 Semi `Nav` 的 `onSelect` 回调手动执行 `navigate()`。

该写法缺少浏览器原生链接兜底，并且对组件库回调参数结构有较强假设。一旦 `onSelect` 在实际运行场景中未按预期触发或参数形态不同，侧栏菜单会只更新视觉状态，不能推动 React Router 路由切换，表现为后台像静态页面。

## 修改范围

- `SiderBar.jsx`
  - 恢复内部菜单项使用 `Link` 作为实际导航承载。
  - `onSelect` 仅负责选中态和子菜单展开态，不再重复执行手动跳转。
  - 兼容 `onSelect` 回调可能返回字符串或对象的情况，避免选中态更新异常。
  - 保留新版新增的通知中心入口、扩展模块可见性过滤等功能。

## 兼容性

- 不改变后端接口、数据模型和权限模型。
- 不改变 classic 路由定义。
- 对桌面端与移动端均保留原有 Link 导航行为；移动端点击菜单后仍会关闭抽屉。

## 验证

- 已执行 classic 前端生产构建：

```bash
npm run build
```

构建通过。输出中的大 chunk、Browserslist 和 `lottie-web` eval 提示为既有构建警告，不影响本次导航修复。

## 回滚

如需回滚，可恢复 `SiderBar.jsx` 至 `v1.0.0-rc.10.1.10.206` 状态；但不建议回滚到只依赖 `onSelect + navigate()` 的实现，因为该实现缺少链接兜底。
