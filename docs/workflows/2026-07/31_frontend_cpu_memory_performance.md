# 前端 CPU 与内存异常修复记录

## 背景

Chrome 打开站点后出现持续卡顿、高 CPU 和高内存。初步只观察强制垃圾回收后的
JS 堆，没有发现 DOM 或监听器持续增长，但进一步对生产构建进行 CPU Profile、
分配采样和页面对照后，确认 Classic 后台存在无限重渲染，首页和 Default 概览还
存在常驻装饰动画，Classic 仪表盘存在图表主题观察器重复注册。

## 根因

- Classic `useSidebar` 每次渲染创建新的 `isModuleVisible` 函数。
- `SiderBar` 的扩展菜单计算依赖该函数，因此每次渲染生成新数组。
- 路由同步 Effect 依赖该数组，并无条件写入新的 `selectedKeys` 数组，形成持续
  重渲染闭环。
- Classic 首页的扫光文字使用无限 `background-position` 动画，Default 概览的
  请求示例使用无限 Motion 位移动画，页面静置时仍持续绘制。
- Classic 图表初始化重复启用主题监听，页面重新进入和图表切换后观察器及图表
  资源不能完整回落。

## 修改范围

- 稳定 Classic 侧栏权限判断函数引用，并在选中项未变化时复用旧状态。
- 将纯装饰动画改为有限播放，并尊重浏览器减少动画偏好。
- 集中管理 Classic VChart 主题初始化和主题切换，避免重复创建主题观察器；保证
  图表切换和页面卸载时实例能够释放。
- 不改变路由、权限、接口、数据模型、配置项或用户可见业务行为。

## 安全与兼容性

- 仅调整前端渲染生命周期和装饰效果，不影响服务端鉴权及侧栏可见性判定。
- Classic 与 Default 分别按现有 React 18/Semi UI 和 React 19/Tailwind/Motion
  约定实现。
- 不升级 VChart 主版本，避免在本次修复中引入图表 API 兼容风险。

## 验证计划

- Classic 与 Default 生产构建通过。
- Classic 后台桌面视口静置时，主线程不再持续占满单核。
- Classic 控制台页面往返后，DOM、事件监听器、MutationObserver 和强制回收后
  JS 堆不再线性增长。
- Classic 首页和 Default 概览静置时不再运行无限装饰动画。
- 侧栏权限、折叠、选中态、扩展菜单及移动端抽屉行为保持正常。
- 执行现有前端专项测试、后端相关测试、静态检查、`git diff --check` 和固定本地
  测试流程。

## 已知边界

- Classic 主入口同步代码和整库动态图标、两套前端全部语言同步加载、操练场长
  会话/Base64 图片、仪表盘大时间范围数据仍属于后续包体和页面级优化方向；本次
  发版优先消除已经实测确认的常驻 CPU 与资源泄漏。
