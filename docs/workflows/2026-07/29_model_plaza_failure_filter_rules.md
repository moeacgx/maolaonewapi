# 模型广场失败过滤规则

## 目标

模型广场的成功率用于表达模型和渠道可用性。内容政策拒绝、业务侧固定拒绝文案或其他
管理员明确认可的错误不应降低该成功率，但原始客户端响应、错误日志、安全审计、计费和
渠道重试行为必须保持不变。

## 配置契约

`perf_metrics_setting.failure_filter_rules` 保存有序规则数组。每条规则包含稳定 ID、名称、
启用状态、匹配字段、匹配方式和多个独立匹配值。最多保存 100 条规则，每条规则最多
保存 64 个匹配值；规则名称不超过 128 个字符，每个匹配值不超过 4096 个字符。ID
最长 64 个字符且必须唯一，只允许 ASCII 字母、数字、
点、下划线和连字符。

新格式使用 `values` 数组保存独立内容项。管理页面中按 Enter 会提交当前内容并新增
下一项，Shift+Enter 保留换行，因此多行完整错误正文不会被错误拆分。旧配置中的单个
`value` 字段仍会自动按一个匹配值读取；保存后可升级为 `values` 数组。匹配值之间使用
OR 语义，任意一个值命中即视为该规则命中。

匹配字段：

- `status_code`：客户端最终 HTTP 状态码的十进制文本，例如 `400`。
- `error_code`：结构化 `NewAPIError` 错误码，例如 `cyber_policy`。
- `message`：脱敏后的错误正文，不含额外状态码前缀。
- `full_error`：`status_code=<状态码>, <脱敏错误正文>` 完整文本。

匹配方式：

- `contains`：区分大小写的包含匹配，适合稳定关键词或一段固定文案。
- `exact`：去除首尾空白后的完整相等匹配。
- `regex`：Go RE2 正则匹配；配置保存时必须编译成功，不支持回溯特性。

启用规则之间以及同一规则内的匹配值都使用 OR 语义，任意一条规则或一个值命中即不写入模型广场失败样本。规则只影响
`perf_metrics`，不改变渠道质量指标、安全审计、客户端状态码、错误正文、重试、自动
禁用或计费。系统内置内容策略错误码仍保持默认排除，不能被自定义规则关闭。

## 兼容性与安全

缺少配置时按空规则处理，保持现有行为。规则只对保存后新产生的样本生效；历史
`perf_metrics` 已聚合且没有错误维度，不能无损反向删除，会随查询和保留窗口自然退出。
匹配使用脱敏错误文本，不把上游密钥、请求正文或鉴权信息写入配置或指标。

例如要排除 OpenAI 内容政策固定文案，可选择 `full_error` + `contains`，匹配值填写：

```text
status_code=400, 非常抱歉，该提示可能违反了OpenAI的内容政策
```

   登录和演示数据接口验证通过；示例规则经 API 保存、重新读取后恢复原配置。
