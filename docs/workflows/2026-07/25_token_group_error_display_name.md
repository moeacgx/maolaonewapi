# 令牌分组错误显示当前名称

## 问题

令牌鉴权失败时，错误文案直接输出令牌保存的稳定分组标识。分组改名后，稳定标识不会
随展示名称变化，因此用户可能看到旧名称或内部别名，误以为系统校验了错误的分组。

## 目标与范围

- 令牌鉴权阶段的“无权访问分组”和“分组已被弃用”错误优先显示当前分组名称。
- 单分组和多分组令牌保持一致。
- 分组查不到或数据库查询失败时回退稳定标识，保证错误处理本身不会阻断鉴权响应。
- 只改变用户可见文案，不改变令牌绑定、稳定标识、权限判断或渠道选择逻辑。

## 方案与安全边界

通过分组标识或历史别名查询结构化分组，取得当前 `name` 后用于格式化错误消息。运行时
仍使用原始稳定标识做权限与倍率校验，不允许展示名称参与权限决策。

## 兼容性

不涉及接口结构、数据库结构或配置迁移。SQLite、MySQL 和 PostgreSQL 均使用现有 GORM
查询路径。无法解析的旧分组仍显示原始值。

## 验证结果

- 覆盖“稳定标识与当前名称不同”的单分组无权限错误。
- 覆盖找不到分组时回退原始标识。
- `go test ./middleware -count=1 -timeout 60s`：通过。
- `go test ./model -run '^TestGetGroupDisplayNameMapIncludesDisabledGroupsAndAliases$' -count=1 -timeout 60s`：通过。
- `git diff --check`：通过；工作区其他文件存在既有换行符警告，本次文件无空白错误。
