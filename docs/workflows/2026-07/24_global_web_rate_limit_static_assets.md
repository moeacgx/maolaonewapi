# 网页静态资源限流隔离

日期：2026-07-24

## 问题

`GlobalWebRateLimit` 原先对网页导航和所有静态资源使用同一个按客户端 IP 计数的
限流桶。默认阈值为 180 秒内 60 次请求。前端版本升级后，浏览器需要重新下载带新
哈希的 JavaScript、CSS、字体和图片；后台切换懒加载页面时还会继续请求页面分块。

生产现场确认同一个客户端 IP 的 Redis 限流键达到 60 条后，`/assets/*`、后台路由
和首页全部返回 429。被拒绝的请求会延长限流键 TTL，浏览器持续重试时无法自行恢复。

## 根因

静态资源请求与 HTML 页面导航没有隔离。一次正常的冷缓存加载和少量页面切换就能
消耗大部分网页限流额度，资源加载失败后产生的重试又会放大问题。

## 修改范围

- `GlobalWebRateLimit` 保留对 HTML 路由和其他非静态请求的现有限流；
- `GET`、`HEAD` 请求的 `/assets/*` 以及常见脚本、样式、字体、图片、媒体和清单文件
  不再占用网页限流额度；
- `POST` 等非只读请求即使使用静态文件后缀也不会绕过限流；
- API、模型请求、搜索和关键操作的独立限流不受影响；
- 不涉及数据库结构或持久业务数据。

## 验证计划

- 同一 IP 可重复读取静态资源而不触发网页限流；
- 同一 IP 的后台 HTML 路由仍按配置阈值返回 429；
- 覆盖 `/assets/*`、根目录图片、`HEAD`、非静态路由和 `POST` 边界；
- 执行 `go test ./middleware -count=1`、`go vet ./middleware`、`gofmt` 和
  `git diff --check`。

## 部署注意事项

代码升级不会自动删除 Redis 中已经存在的 `rateLimit:GW<IP>` 键。紧急恢复已被锁定
的客户端时，只清理确认受影响 IP 对应的临时网页限流键，不得批量清空其他限流键。

## 验证结果

- 新增限流边界测试：通过；
- `go test ./middleware -count=1`：通过；
- `go vet ./middleware`：通过；
- `git diff --check`：通过，仅报告工作区既有文件的 CRLF 转换提示；
- 生产应急回滚后，`zzapi` 容器健康，公网后台路由和当前静态资源均返回 200。
