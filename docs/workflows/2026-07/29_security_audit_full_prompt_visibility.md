# 安全审计保留完整审核正文

## 变更目标

Root 审核员需要看到完整上下文。屏蔽词或上游策略命中事件不能因为没有配置
`CRYPTO_SECRET` 而只剩哈希、字符数和技术元数据，也不能把列表预览强制替换成
不可判断的星号。

## 行为契约

- 审计快照保留完整提取文本，详情接口返回 `full_prompt`。
- 即使某条历史路由只执行屏蔽词过滤或上游策略识别、没有先生成通用快照，事件写入前
  也会从可复用请求体兜底提取正文和 `model`/`model_name` 元数据。
- 配置了稳定 `CRYPTO_SECRET` 时，正文仍使用 AES-GCM 密文保存。
- 未配置密钥时，事件使用明确的 `plaintext_v1` 类型保存，Root-only 详情仍可读取；
  这属于管理员明确可见的审计数据，不与请求归档的加密存储契约混用。
- 列表预览显示正文开头，长度受预览上限限制但不再做内容脱敏；完整正文仍只在详情
  接口返回。
- Default 和 Classic 详情页直接在线渲染完整上下文，同时保留复制正文能力；渲染器不
  执行不受信任 HTML，避免审计正文影响管理页面结构。
- 旧事件如果本来没有保存正文，仍只能显示“正文未保存”；历史数据无法凭哈希恢复。

## 安全边界

事件接口继续受 Root 权限、关键操作限流和 `Cache-Control: no-store` 保护。Guard
节点令牌、请求归档正文和对象存储凭据仍必须使用稳定 `CRYPTO_SECRET` 加密，不能
因为审计事件的明文兼容模式而放宽这些凭据契约。

## 验证计划

- 无 `CRYPTO_SECRET` 时，屏蔽词和上游策略事件仍保存正文并能通过详情接口读取。
- 有 `CRYPTO_SECRET` 时，数据库不出现正文明文，详情接口仍返回完整正文。
- 列表预览显示正文片段；前端详情显示完整上下文和截断状态。
- Default、Classic、Go 单元测试及 `git diff --check` 全部通过。
