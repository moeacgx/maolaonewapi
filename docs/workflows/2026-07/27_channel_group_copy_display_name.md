# 渠道分组复制当前显示名称

## 问题

Classic 渠道管理列表已经通过 `group_details` 展示分组的当前名称，但分组标签的点击
复制逻辑仍固定复制稳定分组标识。分组改名后，用户看到的是新名称，剪贴板中却是旧别名，
界面反馈与实际复制内容不一致。

## 目标与范围

- Classic 渠道列表点击分组标签时，复制标签当前显示的名称。
- 成功提示和复制失败弹窗使用同一显示名称。
- 未配置显示名称或无法解析结构化分组时，继续回退复制稳定分组标识。
- 不改变渠道保存的分组标识、权限判断、倍率计算或渠道调度逻辑。

## 方案与兼容性

`renderGroup` 在每个分组标签渲染前通过 `getGroupDisplayName` 统一解析显示名称，并同时
用于标签文本、剪贴板内容及交互反馈。Default 渠道列表当前不提供分组标签点击复制；其
通用状态标签在启用复制时默认使用展示文本，因此无需修改。

Classic 的渠道和令牌列表共用 `renderGroup`。两处只要提供结构化名称映射，点击复制都
会与可见标签保持一致；未提供映射的用户和日志标签行为不变。

本次仅调整前端展示交互，不涉及接口、数据库结构或数据迁移。

## 验证结果

- 专用测试覆盖存在显示名称和缺少名称时的回退行为，共 2 项通过。
- Classic 目标 ESLint 和 Prettier 检查通过。
- Classic 生产构建通过。
- Default TypeScript 类型检查通过，确认共享数据契约未受影响。
- `git diff --check` 通过。
