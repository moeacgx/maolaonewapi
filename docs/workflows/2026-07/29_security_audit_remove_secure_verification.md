# 安全审计移除通用身份验证

## 变更目标

安全审计已经是 Root-only 管理页面。页面内保存配置、探测 Guard 节点、查看事件
详情和删除事件时不再额外要求 Passkey、两步验证码或通用敏感操作验证令牌。

## 修改范围

- 移除 `/api/security-audit` 下所有路由的 `SecureVerificationRequired` 和
  `CriticalRateLimit` 中间件，仅保留 `RootAuth` 与 `DisableCache`。
- Default 与 Classic 页面不再挂载通用身份验证窗口；保存、探测、详情和删除直接
  调用对应 Root API。
- 内置策略和请求归档原本已经不要求通用身份验证，本次保持不变。

## 保留的令牌契约

- Guard 节点令牌是访问外部 Guard 服务的加密凭据，不是管理员身份验证令牌，继续
  使用 `keep|replace|clear` 契约。
- 按筛选删除的五分钟确认令牌用于绑定删除预览快照，防止误删范围漂移，不触发
  Passkey 或两步验证，继续保留。

## 安全边界与验证

- 所有安全审计接口仍仅允许 Root 访问，普通管理员和普通用户不能调用。
- 写入、探测、详情和删除接口不再使用通用限流，仍仅允许 Root 访问并设置
  `no-store`；按筛选删除的确认令牌继续防止范围漂移。
- 路由测试断言未提供通用验证状态时请求能够进入控制器，而不是返回
  `VERIFICATION_REQUIRED`。
- 两套前端执行类型检查或规则测试，并检查安全审计源码不再引用通用身份验证组件。
