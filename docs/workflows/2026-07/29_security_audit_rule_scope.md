# 安全审计屏蔽词规则作用范围修正

## 变更目标

屏蔽词规则的作用范围应对应实际业务路由对象，而不是关键词预填组或渠道标签。
规则编辑器提供三种模式：全部渠道、指定多个渠道、指定多个业务分组。

## 实现范围

- 移除 Default 与 Classic 编辑器中的“关键词组引用”输入区域；历史 `group_refs`
  仍由后端兼容读取，避免升级时丢失旧配置。
- 新增 `target_type=all`，表示规则对所有渠道生效。
- 新增 `target_type=groups` 与 `group_codes`，按渠道实际绑定的业务分组匹配。
- 新增 Root 接口 `/api/security-audit/builtin-policy/groups`，返回启用业务分组的
  ID、编码和名称；不再使用 `Channel.Tag` 作为规则分组来源。
- 指定渠道仍使用 `channel_ids`，三种目标互斥；启用的指定渠道/指定分组规则必须
  至少选择一个目标。

## 兼容性与安全边界

- 旧 `target_type=channel_tags` 与旧 `group_refs` 保留后端兼容读取，但新页面不再
  创建这两类新配置。
- 分组运行时使用稳定分组编码匹配渠道绑定；分组名称只用于显示，名称修改不会
  破坏规则关联。
- 动态选渠阶段无法可靠解析候选分组时，不提前扩大指定渠道、渠道标签或分组规则的
  作用范围；实际渠道选定后再精确匹配。全部渠道规则仍可在分配前执行，固定渠道重试
  时重新读取当前渠道绑定的业务分组。

## 验证计划

- Go：规则解析、目标校验、动态候选与固定渠道分组匹配测试。
- 前端：三种作用范围切换、渠道/分组多选、全部渠道无需选择项、失效目标保留。
- 文档：执行 `git diff --check`，核对 API 路径和字段契约。
