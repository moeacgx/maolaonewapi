# 屏蔽词客户端错误与状态契约

## 问题

屏蔽词阻断原先返回技术性错误正文。部分客户端只显示错误正文，无法直观看出这是
new-api 的本地内容审计规则。同时，模型广场旧指标链路会把上游 `cyber_policy`
拒绝记录为失败，导致内容违规被误解为模型连接故障。

## 契约

- 服务内部稳定错误码保持 `sensitive_words_detected`，继续用于审计、重试和指标判断；
  客户端响应不暴露该内部分类。
- 普通 HTTP 请求和非流式响应阻断返回 HTTP 403，明确表示内容策略拒绝，而不是请求
  格式错误。
- SSE 在连接和响应头已经建立后命中时保持 HTTP 200，并发送 `event: error`。
- Realtime 发送标准错误事件，并以 WebSocket 4403 关闭。
- 客户端展示正文固定为“内容审计命中风险规则，请调整输入后重试”，随后追加请求编号；
  不在正文中拼接英文、HTTP 状态或内部稳定错误码。
- HTTP 与 SSE 的 OpenAI 错误对象返回 `error.code=null`，且不附带内部 `metadata`。
- 屏蔽词错误继续标记为不可重试，不改变审计事件、计费或上游错误契约。
- `sensitive_words_detected`、`prompt_guard_blocked`、`prompt_blocked`、
  `cyber_policy` 只按稳定结构化错误码识别，继续保留安全审计，但不写入模型广场
  失败样本，也不参与渠道质量成功率。
- 普通 HTTP 400/403、鉴权失败、协议错误和真实连接故障不在过滤范围内。
- HTTP 200 中的 SSE `response.failed` 和 Realtime `cyber_policy` 事件在精确识别后
  标记整次请求，既不记模型成功，也不记渠道连接失败。

## 兼容性

普通 HTTP 阻断状态从 400 调整为 403；客户端不再通过 `error.code` 接收内部分类。
只依赖 HTTP 400 或客户端 `sensitive_words_detected` 判断内容审计的旧客户端，需要
改为识别 HTTP 403 和固定中文正文。SSE 已写出响应头后不能改成 HTTP 403，因此必须
识别 `event: error` 和固定中文正文。SQLite、MySQL 和 PostgreSQL 不涉及数据迁移。升级前已经
写入 `perf_metrics` 的聚合桶没有错误码维度，不能无损反向拆分，会随查询和保留窗口
自然退出；新请求立即按本契约过滤。

## 验证

- 服务层测试校验 HTTP 403、SSE HTTP 200、固定中文正文，并确认客户端响应不泄露
  内部错误码和元数据。
- HTTP 中间件测试校验前置阻断响应。
- Realtime 中间件测试校验错误事件正文与 4403 关闭码。
- 模型广场测试校验内容策略拒绝不写失败桶，真实连接失败仍正常写入。
- 渠道质量测试覆盖实时采集、流式错误优先级和历史日志回填。
