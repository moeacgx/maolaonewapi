# 独立分组与令牌绑定冲突

## 变更目标

给实体分组增加“独立分组”属性。独立分组用于不允许跨分组回落的特殊线路：令牌一旦绑定独立分组，就不得同时绑定其他实体分组或 `auto`。

## 数据契约

- `groups.exclusive` 为布尔字段，默认 `false`。
- `GET /api/group/details` 和 `PUT /api/group/details` 中的分组对象包含 `exclusive`。
- `GET /api/user/self/groups` 的分组选项包含 `exclusive`，供令牌编辑器执行即时冲突限制。
- 令牌的绑定结构不增加字段，独立性始终从当前分组记录判定。
- `PUT /api/group/details` 必须区分 `exclusive` 字段缺失和明确传入 `false`：旧客户端缺失该字段时保留数据库现值，只有明确传入 `false` 才取消独立属性。

## 业务规则

1. 新建或编辑令牌时，独立分组只能单选。
2. 选中普通分组后，不再提供独立分组作为追加选项；选中独立分组后，不再提供任何其他分组。
3. 后端新增和更新令牌时必须重新校验，不信任前端。
4. 将分组设为独立时，不自动改写历史令牌。历史冲突令牌请求 API 时返回 HTTP `503`，消息为“当前绑定分组违规”。
5. 独立分组不能同时加入自动分组顺序，避免 `auto` 绕过独立性。管理界面勾选独立时自动取消该分组的自动分组成员资格，后端仍做强制校验。
6. 独立分组内部的多渠道选择和同分组重试行为不变。
7. 编辑历史令牌时，客户端必须把令牌 `group_details` 合并到当前可用分组选项中。即使某个已绑定的独立分组已不在当前可选列表，仍要显示其独立标记和冲突提示，便于管理员修正历史绑定。
8. 令牌请求的独立性校验不得每次访问数据库；使用进程内独立分组 ID 快照，有效期为 5 秒，并在本进程分组配置提交后立即失效。写路径仍在事务和分组行锁内直接查库强校验。

## 兼容性与迁移

- 使用 GORM `AutoMigrate` 增加布尔列，同时兼容 SQLite、MySQL 和 PostgreSQL。
- 既有分组默认为非独立，升级后原有路由行为不变。
- 滚动升级或浏览器旧页面仍可安全保存其他分组字段，不会因未识别 `exclusive` 而静默关闭独立保护。
- 历史冲突令牌不会在迁移中删除或自动改组，由管理员在令牌编辑页修正。
- 多实例部署中，接收管理请求的实例立即失效快照，其他实例最迟在 5 秒有效期到期后读取新值。

## 测试计划

- 覆盖分组字段的创建、更新和 API 投影。
- 覆盖独立分组单选成功、独立与普通多选失败、普通多分组保持成功。
- 覆盖历史冲突令牌的 `503` 运行时拦截。
- 覆盖 Default 和 Classic 的选择冲突交互、不可选历史分组回显及多语言文案。
- 覆盖旧客户端不传 `exclusive` 时保留原值，以及明确传入 `false` 时可取消。
- 覆盖高频令牌校验仅读快照、分组修改后快照立即刷新。

## 验证结果

- 后端独立分组定向测试通过，包含令牌新增、更新、分组迁移和历史冲突令牌 `503` 拦截。
- 旧客户端缺失 `exclusive` 时保留原值、显式 `false` 取消独立属性的定向测试通过。
- 鉴权快照会复用已加载数据，分组保存或有效期到期后能读取最新独立属性。
- `go test ./controller ./model ./middleware ./service -count=1 -timeout 60s` 通过。
- `go vet ./controller ./model ./middleware ./service` 通过。
- 后端相关 Go 文件格式检查通过，`git diff --check` 通过。
- Classic 历史独立分组回显用例通过，即使该分组不在当前可用列表，编辑器仍能识别冲突。
