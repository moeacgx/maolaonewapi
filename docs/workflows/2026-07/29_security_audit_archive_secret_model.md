# 安全审计归档密钥门禁与模型字段修复

## 问题

- 本地完整请求归档仍被 `CRYPTO_SECRET` 门禁拦截，导致 Root 无法保存归档配置。
- 前置屏蔽词发生在渠道分配前，事件写入时尚未设置 `original_model`，模型列显示为 `-`。

## 修改

- 本地归档不再要求 `CRYPTO_SECRET`。无密钥时使用带 `plain_ra1:` 前缀的明确兼容格式，
  Worker 可以直接投递；已有 `ra2`/`ra3` 加密任务在密钥恢复前保持排队。
- 配置密钥时继续使用 `ra3` AES-GCM 分片信封；S3/R2 凭据仍需要稳定密钥保护。
- 请求正文快照完成后立即写入请求模型上下文，确保前置屏蔽词和后续上游策略事件记录
  客户端请求的模型名称。
- 新增 `request_cipher_format` 字段区分明文兼容任务和历史加密任务，避免无密钥 Worker
  错误领取并失败历史密文。

## 兼容性与安全边界

- 已有加密任务、Guard 令牌和对象存储凭据不改变存储格式；密钥丢失时仍无法解密。
- 明文兼容模式只适用于管理员明确启用的本地完整归档，页面和 API 继续限制 Root 权限。
- 归档正文仍不包含 Authorization、Cookie 和 URL query/fragment。

## 验证

- 无 `CRYPTO_SECRET` 时本地归档配置、入队、Worker 投递和正文读取测试通过。
- 有密钥时原有 `ra3` 加密归档测试通过。
- 前置请求模型会写入安全审计上下文。
