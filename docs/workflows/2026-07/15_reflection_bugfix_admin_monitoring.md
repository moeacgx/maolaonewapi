## 1. 概述

本轮集中修复了输出 Token 计费兼容、发票金额展示、用户精确搜索与角色管理、单渠道监控策略等问题，并审查了单渠道并发上限的完整获取与释放链路。

## 2. 用户需求

- 修复 OpenAI 兼容响应缺失输出 Token 计费的问题。
- 发票列表直接显示开票总金额。
- 用户搜索时支持精确 ID 优先，并增加角色筛选。
- 允许超级管理员安全地授予或撤销超级管理员角色。
- 修复单渠道监控覆盖全局配置、间隔覆盖失效和旧任务覆盖新配置的问题。
- 验证单渠道并发上限是否真正生效。

## 4. 修改内容

### 4.1 输出 Token 计费

- 统一兼容 `completion_tokens`、`output_tokens` 和 `total_tokens` 差值。
- 保留标准字段优先级，防止同义字段重复累计。
- 覆盖普通响应、流式响应和自动聚合响应。

### 4.2 用户与发票管理

- 发票费用列直接显示已保存的开票总金额。
- 数字关键词搜索时将精确用户 ID 排在最前。
- Classic 用户列表增加普通用户、管理员、超级管理员筛选。
- 超级管理员可以创建、提升和降级其他超级管理员，但不能降级自己。
- 权限敏感请求重新读取数据库角色，避免旧会话继续持有已撤销权限。

### 4.3 单渠道监控

- `monitor_enabled` 为空时继承全局，显式值可以覆盖全局开关。
- 调度轮询会考虑单渠道最短间隔，包括短于一分钟的覆盖值。
- 测试前后重新读取渠道，避免使用长耗时测试开始前的旧策略。
- 监控任务只合并运行态字段，并使用比较更新保护管理员的新配置。
- 渠道列表读取失败时释放运行锁，避免监控永久停滞。

### 4.4 单渠道并发

- 确认候选过滤、最终原子占用、失败释放、请求结束释放和重试切换均成对执行。
- 修复并发回归测试复用固定 SQLite 内存地址导致的重复执行失败。

## 5. 遇到的错误

### 错误一：响应 DTO 解析后业务字段全部归零

**类型**：Go JSON 方法提升
**严重程度**：严重

匿名嵌入类型新增 `UnmarshalJSON` 后，该方法被提升到外层响应类型，导致整个响应被当作 usage 对象解析。解决方式是改为具名 usage 字段，并补充外层响应解析测试。

### 错误二：单渠道显式启用仍受全局开关阻断

**类型**：调度与策略分层错误
**严重程度**：重要

策略层支持覆盖，但外层调度器在全局关闭时完全不运行。修复后由每个渠道的有效策略决定是否存在需要调度的渠道。

### 错误三：旧监控任务覆盖管理员新设置

**类型**：并发写入竞态
**严重程度**：重要

监控任务保存启动时读取的整段 JSON。长耗时测试期间管理员修改配置后，旧任务会覆盖新值。修复为重新读取、只合并运行态字段并进行比较更新。

### 错误四：重复测试出现用户主键冲突

**类型**：测试隔离
**严重程度**：次要

SQLite 共享内存 DSN 固定且连接未及时关闭，`-count` 重复运行时复用了上一轮数据库。修复为唯一 DSN 并注册连接清理。

### 错误五：预发布测试仍使用旧函数签名

**类型**：编译期接口漂移
**严重程度**：重要

OpenAI usage 回归测试仍向已简化的 `handleLastResponse` 传入两个旧参数，导致目标包无法编译。修复为让测试与当前函数签名保持一致，并将该包纳入发布前必跑清单。

## 6. 根本原因分析

- 只验证局部字段解析，没有验证外层 DTO 的 Go 方法集变化。
- 单渠道覆盖语义只落实在策略对象，没有追踪到最外层定时调度循环。
- 运行态和配置态共用一个 JSON 字段，却使用整字段覆盖写入。
- 测试默认假设单次运行，未把重复执行作为隔离要求。

## 7. 调试过程

1. 从截图表现反查最终计费、查询、权限和调度入口。
2. 使用定向搜索追踪请求参数、响应 usage、渠道策略和并发许可。
3. 先增加最小回归测试，再修改运行代码。
4. 对监控配置进行测试前后双重读取，验证管理员并发编辑场景。
5. 将关键测试提高到 20 次和 100 次重复运行。

## 8. 经验总结

- Go 匿名嵌入类型增加自定义 JSON 方法属于外层 API 行为变更，必须测试完整响应。
- “继承全局”配置必须同时检查调度层、策略层和执行层，任一层总开关都会破坏覆盖语义。
- 同一字段混合配置态和运行态时，应使用字段级合并与乐观并发控制。
- 权限变更不能只失效缓存；权限敏感路径应以数据库当前角色为准。
