# 模型广场卡片与性能详情展示范围修正

## 问题

- 模型广场卡片需要三段可用状态信号条。
- 早期实现把卡片和性能详情共用的状态条一起压缩为四段，超出了卡片调整范围。

## 根因

- Classic 的 `SuccessRateSparkline` 默认执行最近 24 小时分段聚合，卡片和详情页无法选择不同模式。
- Default 的性能详情直接改用四段 `StatusSegments`，丢失了原有逐点展示。

## 修正方案

- Classic 新增卡片显式传入的 `aggregateWindow` 模式：
  - 模型卡片启用聚合，继续展示三段最佳分组可用状态；
  - 性能详情不启用聚合，恢复最近 24 个原始性能点、原有颜色阈值和悬停信息。
- Default 模型卡片继续使用三段 `StatusSegments`；性能详情恢复原有逐点状态条。
- 不修改 `status_rate` 接口契约、性能指标采集、计费、分组或渠道选择逻辑。

## 兼容与安全

- 只调整前端展示模式，不涉及数据库迁移和生产数据更改。
- 模型卡片仍在旧后端缺少 `status_rate` 时回退至 `success_rate`。
- 性能详情继续使用真实分组成功率，不使用最佳分组口径。

## 测试计划

1. Classic 测试覆盖卡片显式启用聚合、详情使用 24 个原始点。
2. Default 测试覆盖卡片使用三段状态、详情不依赖聚合状态组件。
3. 执行两套前端定向测试、Default 类型检查、两套生产构建和差异检查。
4. 使用固定 `3000/3001` 本地测试入口验证模型卡片与性能详情，完成后停止测试服务。
