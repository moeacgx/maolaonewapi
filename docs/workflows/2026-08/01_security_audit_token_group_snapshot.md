# 安全审计令牌绑定分组快照

## 目标

安全审计事件需要同时展示令牌在事件发生时绑定的分组，以及本次请求最终实际使用的
路由分组。两者必须分开记录，便于判断显式多分组令牌、`auto` 令牌和跨分组回落行为，
不再用渠道绑定分组代替令牌配置。

## 数据契约

- 事件新增 `token_group_mode`，保存令牌当时的 `explicit`、`auto`、`inherit` 或
  `none` 模式。
- 事件新增 `token_groups`，保存令牌当时绑定分组的 ID、稳定编码和显示名称快照。
- `explicit` 模式保存全部结构化绑定；旧上下文只有分组编码时按编码解析并保持顺序。
- `auto` 模式的页面直接显示 `auto`，不把最终回落分组冒充为令牌绑定。
- `inherit` 模式保存事件发生时继承的用户分组 ID 和稳定编码；已有名称时一并保存。
- Canvas、Playground 等无真实令牌的站内请求保存 `none`，不能把临时路由分组误记为
  令牌绑定分组。
- `group_id`、`group_code`、`group_name` 继续表示本次实际路由或选渠前候选分组。
- 既有 `channel_groups` 保留在接口中用于历史兼容，不再作为管理页展示字段。

快照在事件产生时固化。令牌或分组后续修改、停用、迁移或删除，不改变历史事件。
升级前事件没有新字段时，页面显示“历史事件未记录”，不得查询当前令牌配置进行猜测。

## 兼容性与安全边界

- 分组快照使用普通 `TEXT` JSON 持久化，由 GORM 迁移，兼容 SQLite、MySQL 和
  PostgreSQL。
- JSON 编解码使用 `common` 包装函数。
- 列表和详情只读取事件自身快照，不在列表热路径逐条查询令牌或分组表。
- 正常鉴权把已水合的令牌分组详情带入请求上下文，事件快照直接复用；继承模式使用
  用户分组 ID 和编码，避免在安全审计中间件中给每个请求增加数据库查询。
- 无法解析的旧显式分组引用保留模式，但只保存能够确认身份的分组，避免伪造名称。

## 页面行为

- 列表与详情新增“令牌绑定分组”。
- 显式单分组或多分组展示全部快照项；`auto` 显示 `auto`；继承模式展示继承结果。
- `none` 显示“未绑定”，不展示临时路由分组；未知模式按历史事件处理。
- “分组”继续展示最终实际路由分组，便于直接对照是否发生跨分组回落。
- 不恢复“渠道绑定分组”展示。

## 测试计划

- 覆盖事件创建、更新、列表、详情和过期异步任务的快照往返与历史空值。
- 覆盖 `explicit` 单/多分组、`auto`、`inherit`、`none` 和旧编码回退解析。
- 覆盖 Default 与 Classic 的列表、详情、历史事件和多语言显示。
- 执行 Go 定向测试、两套前端专项测试、类型检查、生产构建和 `git diff --check`。

## 验证结果

- Go `model`、`service`、`controller`、`middleware` 定向测试通过，覆盖持久化往返、
  显式多分组、`auto`、继承、旧编码回退、同步事件、异步任务快照和接口序列化。
- Default 40 项、Classic 31 项安全审计专项测试通过；Default 类型检查和 Classic
  改动文件定向 ESLint 通过。
- Default 与 Classic 生产构建通过，全部新增多语言 JSON 可解析，Markdown 格式检查和
  `git diff --check` 通过。
- SQLite 旧库缺少 `request_archive_jobs.dedupe_key` 时，主迁移会先增加普通可空列，
  再由 GORM 创建唯一索引；升级回归测试确认重复去重键仍被拒绝。
- 固定复用 `tmp-local-v10101.db` 在 `3000`、`3001` 启动通过，状态接口、Classic
  首页、Root/Demo 登录及演示数据接口验证通过；停止后两个端口均无监听进程。
