# 令牌周期额度限制

## 目标

为单个 API 令牌增加可选的周期额度上限，管理员可以在令牌设置中选择
1 天或 7 天周期并填写额度。周期额度用于限制失控 Agent 在短时间内的
最大消耗，不能替代令牌现有的生命周期额度和过期时间控制。

## 范围

- 令牌周期模式支持 `none`、`daily`、`weekly`；关闭模式不增加额外限制。
- 周期按自然日/自然周计算，并在周期窗口切换后自动开始新的使用量统计。
- 周期额度为非负值，`0` 表示不启用；服务端负责校验上限和规范化输入，不能
  仅依赖前端限制。
- 普通 HTTP、Realtime 以及异步任务的预扣费都必须经过同一套令牌额度检查。
  预扣、结算差额和退款需要同步维护周期使用量，避免并发请求绕过上限。
- 令牌缓存、创建/更新接口和 Default 令牌表单同步暴露该配置；未配置的旧令牌
  保持原有行为。Classic 界面若未同步支持，仍可通过 API 管理配置。

## 数据与接口契约

- 沿用现有令牌接口：`GET /api/token/` 返回配置，`POST /api/token/` 创建令牌，
  `PUT /api/token/` 更新令牌；不新增绕过权限校验的周期额度接口。请求字段示例：

  ```json
  {
    "quota_period": "daily",
    "quota_period_limit": 1000000
  }
  ```

  `quota_period` 仅接受 `none`、`daily`、`weekly`；`quota_period_limit` 使用
  与 `remain_quota` 相同的内部额度单位。前端展示的货币/Token 数值必须沿用现有
  额度换算，服务端不能信任客户端换算结果。
- 令牌记录持久化周期模式、周期额度、当前周期标识和当前周期已用额度。周期
  标识用于在窗口变化时惰性重置使用量，不能通过查询业务日志临时汇总，因为日志
  可能关闭、延迟写入或存储在独立数据库。
- 读取响应可提供 `quota_period_used` 与 `quota_period_reset_at`，用于展示当前
  周期状态；这两个字段是服务端账本的只读结果，客户端不得自行写入或重置。
- 令牌创建和更新接口返回与接受周期配置；更新时只允许管理员修改令牌额度，
  不改变令牌密钥、归属用户和已有权限边界。
- 当本次预扣会超过周期额度时，接口返回与余额不足一致的额度错误，并且不产生
  部分扣费；并发预扣必须以原子操作完成“检查并累加”。
- `UnlimitedQuota` 只豁免令牌生命周期余额检查，不豁免显式设置的周期额度，
  以确保“无限余额”令牌仍能限制 Agent 的日/周消耗。

## 安全与兼容性

- 周期额度使用与数据库额度相同的饱和、非负和溢出保护，拒绝负数、NaN、无穷
  或超出存储范围的输入；不能把超大值转换为有符号整数后发生环绕。
- Redis 预扣和数据库回退路径必须保持相同的周期窗口与原子语义；缓存失效、
  重建和多实例部署不能把已用额度清零或重复计算。
- 结算失败、请求取消、异步任务失败和退款都要回滚相应的周期预扣；重复结算
  只能生效一次。周期重置不删除令牌历史使用记录。
- 迁移适配 SQLite、MySQL 5.7.8+ 和 PostgreSQL 9.6+，旧数据库字段采用安全
  默认值，升级后未配置令牌不受影响。

## 验证计划

- 模型/迁移测试：旧令牌默认值、三种模式规范化及三种数据库兼容路径。
- 额度并发测试：同一令牌的并发预扣在达到日/周上限时只能成功到上限，失败请求
  不改变已用额度；窗口切换后可正常使用。
- 生命周期测试：结算差额、退款、Realtime 和异步任务均正确更新周期账本，
  `UnlimitedQuota` 仍受周期上限约束。
- API/前端测试：创建、编辑、读取配置和超限错误；旧客户端省略字段时保持兼容。
- 交付前执行相关 Go 测试（单次超时 60 秒）、Default 前端类型检查、Markdown
  格式检查和 `git diff --check`。

## 已知限制

- 周期窗口按服务器配置的自然日/自然周边界计算；跨时区部署前应统一实例时区，
  否则不同节点可能在边界附近显示不同的剩余额度。
- 周期账本只记录令牌额度消耗，不改变用户余额、订阅额度或业务日志的展示口径；
  管理员仍需通过现有日志查看请求明细。
