# 充值确认实付金额手续费提示

## 变更目标

充值确认弹窗的最终付款金额需要明确标注为已包含手续费，避免用户把充值数量与实付金额之间的差额误认为计算错误。

## 展示范围

- Classic 充值页 `/console/topup` 的充值确认弹窗。
- Default 钱包页 `/wallet` 的支付确认弹窗。
- 实付金额标签统一表达为“实付金额（含手续费）”；其他语言使用等义翻译。
- 提示只放在最终实付金额标签处，不新增说明卡片或重复金额行，保持桌面端和移动端确认弹窗紧凑。

## 金额与接口契约

- 展示金额继续使用现有金额预览接口返回的最终付款金额；本次不在前端重新计算手续费。
- 当前最终付款金额已经包含支付配置产生的价格调整，以及申请发票时适用的发票服务费；折扣、优惠码、分组倍率和支付币种格式仍沿用原逻辑。
- 不新增或修改 API、请求字段、响应字段、数据库结构、支付订单金额或结算行为。
- 加载中仍显示原有骨架屏；金额计算失败时沿用现有错误与回退行为。

## 兼容性与安全边界

- 这是纯展示文案变更，不改变后端作为金额权威来源的边界。
- Classic 继续使用中文源键，覆盖现有 `en`、`fr`、`ja`、`ru`、`vi`、`zh-CN`、`zh-TW`、`zh` 语言文件。
- Default 使用英文源键，覆盖 `en`、`fr`、`ja`、`ru`、`vi`、`zh` 语言文件。
- 回滚时只需恢复两个确认弹窗标签并移除对应翻译键，不影响历史订单。

## 验证计划

1. 在固定本地测试环境打开 Classic 充值确认弹窗，确认实付金额标签显示“实付金额（含手续费）”，金额仍为服务端预览结果。
2. 检查中文标签加长后，桌面端弹窗的标签与金额不重叠、不换行错位。
3. 执行 Default 类型检查与生产构建、Classic 生产构建、Default i18n 同步和 `git diff --check`。
4. 确认两套前端所有受支持语言都有非空翻译。

## 验证结果

- 固定本地测试环境的 `/api/status`、Classic 首页、`root` / `demo` 默认账号登录和演示数据接口验证通过。
- Classic 充值确认弹窗在 `1280 × 800` 桌面视口和 `390 × 844` 移动视口均显示“实付金额（含手续费）”；标签与金额没有重叠或异常换行，服务端预览金额保持为 `7.3 元`。
- Default `npm run typecheck` 与生产构建通过；Classic 生产构建通过。
- Default i18n 同步后六种语言均为 `missingCount=0`、`extrasCount=0`；Classic 八种语言和 Default 六种语言的手续费提示均为非空翻译。
- 修改文件通过 Prettier 与 `git diff --check`。
