# 安全审计事件渠道筛选与列表展示

## 问题

审计事件虽然已经固化实际渠道，但管理页只能查看渠道，不能按渠道筛选。Classic 仍直接
显示 `pass`、`critical`、`low` 等稳定值，两套页面的已知风险分类也没有统一翻译。正文
预览占用较宽列且不能隐藏，命中的屏蔽词只能进入详情后查看，不利于 Root 批量审核。

## 方案

- 事件筛选新增 `channel_id`，按事件快照中的实际渠道 ID 精确匹配。
- 列表、删除预览和按筛选删除复用同一筛选结构；确认令牌哈希包含渠道条件。
- Root 列表接口批量读取事件关键词密文并解密为 `matched_keywords`，不序列化内部密文。
- Default 与 Classic 都增加渠道下拉筛选、风险等级和风险分类列、命中关键词列。
- 判定、风险等级和九类已知风险分类按当前语言显示，未知分类保留上游原文。
- 两套页面都提供勾选式列显隐；正文预览可隐藏，操作列不可隐藏，状态不持久化。

## 安全与兼容性

事件接口继续使用 `RootAuth`。关键词只在 Root 列表和详情响应中解密，数据库密文不会
进入响应；历史事件和没有命中关键词的事件返回空数组。渠道筛选只使用不可变 ID 快照，
渠道后续改名、停用或删除不会改写历史事件。新增查询条件使用 GORM，兼容 SQLite、
MySQL 和 PostgreSQL。

## 验证

- 模型测试覆盖渠道精确筛选和关键词密文批量读取。
- 控制器测试覆盖查询参数、删除请求结构和列表关键词 JSON 字段。
- 服务测试覆盖仅使用渠道条件的删除预览、确认令牌和实际删除范围。
- Default 静态测试覆盖渠道条件、列设置、中文化标签和双前端关键词展示。
- Default 与 Classic 分别执行格式化；Classic ESLint 和 Go 定向测试通过。
