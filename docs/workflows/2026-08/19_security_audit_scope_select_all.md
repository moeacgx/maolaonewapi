# 安全审计规则范围全选

## 问题

安全审计的屏蔽词规则和官方风控规则支持全部范围语义，但指定渠道、指定分组的
多选下拉只展示单个真实选项，管理员无法在保留指定范围语义时一次选中当前全部
渠道或分组。

## 方案

- Default 多选组件增加可选的全选操作，由调用方显式传入允许全选的真实值。
- Classic 在对应下拉中增加“全部渠道”和“全部分组”虚拟选项。
- 虚拟选项只负责交互，选择后立即展开为真实渠道 ID 或稳定分组编码，禁止写入
  `channel_ids`、`group_codes`、`upstream_policy_channel_ids` 或
  `upstream_policy_group_codes`。
- 已失效但为兼容旧配置而展示的渠道或分组不纳入全选，避免重新保存无效目标。

## 兼容性与安全边界

本次不修改后端接口、数据库或运行时匹配语义。`target_type=all` 仍表示规则对所有
渠道全局生效；指定范围中的全选仅表示保存操作当时所有可用的具体目标，之后新增
渠道或分组不会自动进入该规则。

## 验证

- Default 单元测试覆盖全选、再次清空、去重及空列表行为。
- Classic 契约测试确认两个虚拟选项会展开为真实列表。
- 执行 Default 类型检查、相关测试、Classic 契约测试和 `git diff --check`。
