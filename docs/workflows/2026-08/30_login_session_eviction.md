# 登录新会话自动淘汰旧会话

## 目标

活跃登录会话达到容量时，不再返回 `AUTH_SESSION_LIMIT` 阻止用户登录；
新登录成功后自动撤销最久未活跃的旧会话。

## 修改范围

- 所有密码、2FA、Passkey、OAuth、微信和 Telegram 登录继续共用
  `CreateUserSessionWithLimits`。
- 在用户级事务锁内检查活跃会话数量。达到 `USER_SESSION_ACTIVE_LIMIT` 时，
  按 `last_active_at`、`created_at`、`sid` 升序选择并撤销旧会话，再创建新会话。
- 历史数据已经超过容量时会循环淘汰，直到新会话创建后不超过配置容量。
- 淘汰原因记录为 `login_session_evicted`。提交事务后为被淘汰会话发布 Redis
  撤销 tombstone，防止缓存继续接受旧设备请求。
- `USER_SESSION_ISSUANCE_LIMIT` 和对应滚动时间窗口保持不变，用于限制短时间内
  反复登录，不会因为自动淘汰而绕过签发限流。

## 兼容性与安全边界

- `AUTH_SESSION_LIMIT` 不再由正常登录流程产生；达到活跃容量时旧设备会退出，
  新设备获得有效登录会话。
- 并发登录仍由用户行锁和 SQLite 进程内互斥串行化，活跃会话数量不会超过容量。
- 如果新会话写入因签发窗口限制或数据库错误失败，事务会回滚，已选中的旧会话
  不会被单独撤销。

## 验证计划

- 覆盖容量满时淘汰最旧会话。
- 覆盖历史超容量数据的循环淘汰。
- 覆盖并发登录成功且活跃数量保持在容量内。
- 覆盖签发窗口限制仍然生效。
- 执行 `gofmt`、相关 Go 测试、`git diff --check`。
