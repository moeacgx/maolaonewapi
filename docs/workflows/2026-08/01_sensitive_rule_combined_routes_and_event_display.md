# 屏蔽词组合范围与审计路由展示完善

## 目标

屏蔽词规则需要同时支持指定渠道和指定业务分组，避免管理员为了覆盖两类路由创建重复
规则。审计事件页面只展示本次实际渠道和实际路由分组，移除容易与实际分组混淆的
“渠道绑定分组”。

## 配置契约

- 新增 `target_type=routes`，同时承载 `channel_ids` 和 `group_codes`。
- 两个数组至少一个非空；命中任一指定渠道或任一指定业务分组即生效。
- `routes` 禁止携带 `channel_tags`，`all` 禁止携带任何目标数组。
- 历史 `channels`、`groups`、`channel_tags`、`all` 和无 `target_type` 规则继续兼容读取。
- 两套管理页把历史 `channels`、`groups` 和无类型规则转换为组合范围草稿，首次保存写成
  `routes`；历史 `channel_tags` 以只读兼容态保留，避免普通保存丢失目标。

## 页面行为

- 规则目标提供“全部渠道”和“指定范围”两种模式。
- 指定范围同时显示渠道多选和业务分组多选，摘要分别显示两类目标数量。
- 启用且有内容的规则只有在渠道、分组都为空时才禁止保存。
- 审计列表和详情保留“渠道”“分组”，移除“渠道绑定分组”。后端与接口继续保留
  `channel_groups` 快照，不做数据库迁移。

## 路由分组语义

响应、SSE、Realtime 上游响应和跨分组重试后产生的事件使用最终实际选中的渠道与分组。
请求在选渠前已被阻断时不存在最终渠道或分组，仍按分配前候选语义记录并显示“尚未
分配”，不伪造事后路由结果。

## 兼容性与安全边界

本次只扩展 JSON 配置契约，不新增数据库字段。保存端与运行时均独立校验目标组合；非法
组合不能发布到屏蔽词热路径。三种数据库行为不受影响。发布时应先升级支持 `routes` 的
后端，再开放新前端，避免旧后端把未知目标类型规范化为空。
