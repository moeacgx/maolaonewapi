# 渠道监控自动恢复

**日期**：2026-08-06
**类型**：bugfix

## 问题

渠道监控的“成功时自动启用”只在“测试所有渠道”链路中累计连续成功次数。普通请求和
跨渠道重试继续使用普通渠道选择逻辑。

单 Key 渠道探测成功并达到阈值后，旧链路虽然会把数据库状态、Ability 和渠道对象状态
改成启用，但不会把渠道重新加入内存中的分组/模型候选池。页面可显示已启用，业务请求却
仍选不到该渠道，必须等下一次全量渠道缓存同步才真正恢复。

多 Key 渠道的普通选择器只允许使用状态为启用的 Key。当同一渠道的所有 Key 都因上游
错误被自动禁用时，渠道状态会变为自动禁用，但后续监控仍然无法选择任何 Key，直接得到
`no enabled keys`，因此没有机会验证上游是否已经恢复，连续成功次数也不会增长。

## 根因

单 Key 自动恢复沿用了通用状态更新函数。该函数在禁用时会从
`group2model2channels` 删除渠道，但启用时只修改 `channelsIDM` 中的状态，不重建选渠
索引。不能直接给通用函数增加插回逻辑，因为它在数据库保存前更新缓存，数据库或 Ability
写入失败时会把仍处于禁用状态的渠道提前暴露给业务流量。

渠道内多个 Key 是同一渠道的凭据池，不等同于用户 API 令牌。普通请求在多 Key 渠道内
可以先换用另一个启用 Key；根据错误类型和重试配置，后续才可能排除当前渠道并切换到
其他渠道。普通选择器不能放宽为使用已禁用 Key，否则会把明确淘汰的凭据重新用于业务流量。

系统监控使用 Root 用户身份构造内部测试上下文，但不会查找或轮询用户 API 令牌。测试请求
实际发送上游时使用当前渠道自己的 Key；Root 用户上下文只提供内部请求需要的用户和分组信息。

## 修改范围

- 新增仅供监控使用的 Key 选择入口。
- 普通请求、渠道重试和任务重试继续使用 `GetNextEnabledKey`，不探测已禁用 Key。
- 单 Key 监控成功后使用专用恢复入口：事务内重新校验渠道仍为自动禁用、仍是单 Key，
  且 Key 内容与本次实际探测值一致；随后在同一事务内启用渠道和 Ability。探测期间 Key
  被替换、渠道改成多 Key 或被手动禁用时，本次恢复作废。
- 单 Key 与多 Key 的监控恢复都会在事务内重新解析数据库中的最新渠道设置，确认连续成功
  次数仍达到最新阈值且成功自动启用仍开启；自动任务还会复核自动监控与 `auto_ban`。
  管理员在探测后关闭开关或提高阈值时，旧探测结果不会覆盖新策略。手工“测试所有渠道”
  仍可忽略自动监控与 `auto_ban`，但不能绕过成功自动启用开关和成功阈值。
- 单 Key 数据库事务提交后才更新缓存，并立即把渠道幂等加入全部分组/模型候选池；缓存条目
  缺失时从数据库全量重载并复核，避免数据库显示启用但业务选渠仍不可见。
- 监控正常优先选择启用 Key；只有多 Key 渠道没有任何启用 Key 时，才从自动禁用 Key
  中选择一个恢复探测。
- 手动禁用的 Key 不参与恢复探测。
- 探测成功后携带监控上下文中的多 Key 索引和 Key 内容恢复本次实际探测的 Key；
  数据库事务会锁定渠道行，并再次确认整体仍为自动禁用、索引未变化、Key 内容一致且
  该索引仍为自动禁用。SQLite 使用原始渠道状态、Key 和 `channel_info` 做条件更新，补足其
  不支持 `FOR UPDATE` 的差异。配置被替换、重排、删除或改为手动禁用时，本次恢复作废。
  渠道状态与 Ability 启用在同一事务提交，任一步失败都不会通知成功；提交后在与全量缓存
  重载串行化的临界区内，按索引和 Key 内容定向恢复缓存对象及分组/模型候选索引，避免已启用
  渠道在内存选渠中继续缺席，也不会用旧事务快照覆盖并发轮换后的 Key。缓存对象状态变化
  与业务选 Key 使用同一渠道锁；缓存条目缺失时从已提交数据库状态重载并复核，重载失败或
  状态不再匹配时不通知成功。即使配置中存在重复 Key 字符串，也只恢复实际探测的索引。
  达到连续成功阈值后才恢复渠道状态。
- 普通选择与恢复扫描之间若发生并发状态变化，会重新选择一次，避免把已经恢复的渠道
  误记为本轮失败。
- 渠道测试的本地准备错误视为失败，只更新监控计数，不触发渠道自动禁用，也不允许
  自动启用。
- 监控运行态计数保存失败时放弃本轮启停，避免使用未落库的成功或失败次数执行状态变更。
- 单 Key 与多 Key 的缓存恢复共用候选池重建逻辑，均按渠道优先级重新排序且不会重复插入。

## 行为契约

定时自动恢复要求：

- 渠道状态是自动禁用，而不是手动禁用；
- 自动监控和成功自动启用的有效策略均为开启；自动禁用开关不参与恢复判定；
- 渠道 `auto_ban` 开启且运行节点是 Master；
- 探测结果无错误，并达到全局或单渠道连续成功阈值。

管理员手工执行“测试所有渠道”沿用既有手工测试语义：可在任意节点忽略自动监控和
`auto_ban` 开关执行探测，但仍不会测试整体手动禁用的渠道，并且只有成功自动启用开关开启、
达到连续成功阈值且探测目标在事务校验时仍保持自动禁用，才会恢复渠道。

## 安全与兼容性

- 不改变普通流量的 Key 禁用、同渠道 Key 故障转移和跨渠道重试规则。
- 普通单 Key 渠道遇到已配置为可重试的 429 时，仍会在当前分组排除当前渠道并选择下一个
  候选渠道；多 Key 能力不会改变该单 Key 规则。
- 不探测或恢复手动禁用的 Key。
- SQLite 恢复更新使用渠道状态、Key、渠道类型配置和监控设置原始值进行 CAS；恢复只修改
  必要状态，不覆盖并发更新的 `other_info`。MySQL 和 PostgreSQL 继续使用行锁串行校验。
- 事务内使用无副作用的设置解析；损坏的 `settings` 会使本轮恢复失败，不会在持有渠道行锁时
  通过其他数据库连接尝试修复同一行。
- 不新增数据库字段或迁移，SQLite、MySQL 和 PostgreSQL 行为不变。
- 不记录或输出渠道 Key 内容。
- 如果数据库已经提交，但定向缓存恢复和紧接着的全量缓存重载同时失败，后台周期缓存同步会
  继续收敛到已提交状态；在当前节点确认可选前不会发送恢复成功通知。

## 测试

- 覆盖有启用 Key 时监控仍优先使用启用 Key。
- 覆盖所有 Key 自动禁用时可以选择恢复探测 Key。
- 覆盖所有 Key 手动禁用时仍拒绝探测。
- 覆盖单 Key 自动恢复后，数据库渠道状态、Ability 和内存选渠候选池同步启用。
- 覆盖单 Key 探测期间 Key 被替换、渠道被手动禁用或改为多 Key 时拒绝恢复。
- 覆盖单 Key Ability 更新失败时事务回滚，数据库和缓存均不启用。
- 覆盖单 Key 缓存条目缺失时从已提交数据库状态重建并恢复选渠。
- 覆盖恢复前关闭成功自动启用、关闭自动监控、关闭 `auto_ban` 或提高成功阈值时拒绝恢复；
  覆盖手工测试仍可忽略自动监控和 `auto_ban`。
- 覆盖损坏的渠道 `settings` 会快速拒绝恢复，不触发事务外修复写入。
- 覆盖监控上下文的并发许可在 Key 选择失败时释放。
- 覆盖本地测试错误不会被误算为成功。
- 覆盖重复 Key 字符串时按实际探测索引恢复。
- 覆盖探测期间 Key 被替换时拒绝恢复。
- 覆盖探测期间 Key 改为手动禁用时拒绝恢复。
- 覆盖 SQLite 保留原始 `channel_info` JSON 存储字节时仍可执行 CAS，不依赖重新序列化结果。
- 覆盖 Ability 更新失败时渠道状态和单 Key 状态随事务回滚，不报告恢复成功。
- 覆盖内存缓存开启时，恢复后立即重新进入分组/模型选渠候选索引。
- 覆盖缓存条目缺失时通过数据库重载补偿，并在复核成功后才报告恢复。
- 覆盖监控只回退到自动禁用 Key，不使用手动禁用 Key。

验证命令：

```powershell
go test ./model ./middleware ./controller ./service -count=1 -timeout 60s
go test ./... -run '^$' -count=1 -timeout 60s
go vet ./model ./middleware ./controller ./service
git diff --check
```

验证结果：

- 单 Key、多 Key 恢复与单 Key 429 跨渠道定向测试连续 20 轮通过；
- `go test ./model ./middleware ./controller ./service -count=1 -timeout 60s` 通过；
- `go test ./... -count=1 -timeout 60s` 通过；
- `go test ./... -run '^$' -count=1 -timeout 60s` 通过；
- `go vet ./model ./middleware ./controller ./service` 通过；
- `git diff --check` 通过；
- 当前环境为 `windows/386`，Go race detector 不支持该目标，因此未执行 `go test -race`；
- `go vet ./...` 仍会报告仓库既有的 `common.CustomEvent` 复制锁和多个旧渠道适配器不可达
  代码告警，本次未修改这些无关文件。

## 回滚

回滚单 Key 专用事务恢复和多 Key 监控专用选择入口即可恢复原行为；普通请求选择器和
数据库结构无需回滚。
