# 渠道监控自动恢复探测

**日期**：2026-08-06
**类型**：bugfix

## 问题

渠道监控的“成功时自动启用”只在定时的“测试所有渠道”链路中累计连续成功次数。
普通请求和跨渠道重试继续使用普通渠道选择逻辑。

多 Key 渠道的普通选择器只允许使用状态为启用的 Key。当同一渠道的所有 Key 都因上游
错误被自动禁用时，渠道状态会变为自动禁用，但后续监控仍然无法选择任何 Key，直接得到
`no enabled keys`，因此没有机会验证上游是否已经恢复，连续成功次数也不会增长。

## 根因

渠道内多个 Key 是同一渠道的凭据池，不等同于用户 API 令牌。普通请求在多 Key 渠道内
可以先换用另一个启用 Key；根据错误类型和重试配置，后续才可能排除当前渠道并切换到
其他渠道。普通选择器不能放宽为使用已禁用 Key，否则会把明确淘汰的凭据重新用于业务流量。

## 修改范围

- 新增仅供监控使用的 Key 选择入口。
- 普通请求、渠道重试和任务重试继续使用 `GetNextEnabledKey`，不探测已禁用 Key。
- 监控正常优先选择启用 Key；只有多 Key 渠道没有任何启用 Key 时，才从自动禁用 Key
  中选择一个恢复探测。
- 手动禁用的 Key 不参与恢复探测。
- 探测成功后携带监控上下文中的多 Key 索引和 Key 内容恢复本次实际探测的 Key；
  数据库事务会锁定渠道行，并再次确认整体仍为自动禁用、索引未变化、Key 内容一致且
  该索引仍为自动禁用。SQLite 使用原始渠道状态、Key 和 `channel_info` 做条件更新，补足其
  不支持 `FOR UPDATE` 的差异。配置被替换、重排、删除或改为手动禁用时，本次恢复作废。
  渠道状态与 Ability 启用在同一事务提交，任一步失败都不会通知成功；提交后在与全量缓存
  重载串行化的临界区内，按索引和 Key 内容定向恢复缓存对象及分组/模型候选索引，避免已启用
  渠道在内存选渠中继续缺席，也不会用旧事务快照覆盖并发轮换后的 Key。缓存对象状态变化
  与业务选 Key 使用同一渠道锁；缓存条目缺失时从已提交数据库状态重载并复核，重载失败或
  状态不再匹配时不通知成功。即使配置中存在重复 Key 字符串，也只恢复实际探测的索引。
  达到连续成功阈值后才恢复渠道状态。
- 普通选择与恢复扫描之间若发生并发状态变化，会重新选择一次，避免把已经恢复的渠道
  误记为本轮失败。
- 渠道测试的本地准备错误视为失败，只更新监控计数，不触发渠道自动禁用，也不允许
  自动启用。

## 行为契约

定时自动恢复要求：

- 渠道状态是自动禁用，而不是手动禁用；
- 自动监控和成功自动启用的有效策略均为开启；自动禁用开关不参与恢复判定；
- 渠道 `auto_ban` 开启且运行节点是 Master；
- 探测结果无错误，并达到全局或单渠道连续成功阈值。

管理员手工执行“测试所有渠道”沿用既有手工测试语义：可在任意节点忽略自动监控和
`auto_ban` 开关执行探测，但仍不会测试整体手动禁用的渠道，并且只有成功自动启用开关开启、
达到连续成功阈值且探测目标在事务校验时仍保持自动禁用，才会恢复渠道。

## 安全与兼容性

- 不改变普通流量的 Key 禁用、同渠道 Key 故障转移和跨渠道重试规则。
- 不探测或恢复手动禁用的 Key。
- 不新增数据库字段或迁移，SQLite、MySQL 和 PostgreSQL 行为不变。
- 不记录或输出渠道 Key 内容。

## 测试

- 覆盖有启用 Key 时监控仍优先使用启用 Key。
- 覆盖所有 Key 自动禁用时可以选择恢复探测 Key。
- 覆盖所有 Key 手动禁用时仍拒绝探测。
- 覆盖监控上下文的并发许可在 Key 选择失败时释放。
- 覆盖本地测试错误不会被误算为成功。
- 覆盖重复 Key 字符串时按实际探测索引恢复。
- 覆盖探测期间 Key 被替换时拒绝恢复。
- 覆盖探测期间 Key 改为手动禁用时拒绝恢复。
- 覆盖 SQLite 保留原始 `channel_info` JSON 存储字节时仍可执行 CAS，不依赖重新序列化结果。
- 覆盖 Ability 更新失败时渠道状态和单 Key 状态随事务回滚，不报告恢复成功。
- 覆盖内存缓存开启时，恢复后立即重新进入分组/模型选渠候选索引。
- 覆盖缓存条目缺失时通过数据库重载补偿，并在复核成功后才报告恢复。
- 覆盖监控只回退到自动禁用 Key，不使用手动禁用 Key。

验证命令：

```powershell
go test ./model ./middleware ./controller ./service -count=1 -timeout 60s
go test ./... -run '^$' -count=1 -timeout 60s

```

## 回滚

回滚监控专用选择入口即可恢复原行为；普通请求选择器和数据库结构无需回滚。
