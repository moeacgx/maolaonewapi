# `.244` 数据看板与模型广场指标回归修复

日期：2026-08-18

## 问题

`.244` 集成后，Classic 与 Default 数据看板请求
`GET /api/data/revenue` 返回 404。模型广场的
`GET /api/perf-metrics/summary` 虽然返回 200，但历史窗口中的模型列表为空，
导致延迟、吞吐量和状态均显示无数据。

## 根因

- `.244` 集成删除了 `.243` 已有的收入统计控制器、模型查询和路由注册。
- 性能摘要查询只使用当前分组编码过滤数据，未展开仍保存在历史指标中的分组别名，
  因此迁移过分组编码的历史样本被排除。

## 修改范围

- 恢复管理员收入统计接口 `GET /api/data/revenue`，请求和响应契约保持与 `.243` 一致。
- 性能摘要和模型详情查询兼容当前分组编码及其历史别名。
- 保留 `.244` 当前认证、RelayKit 和前端架构，不回退其他集成内容。

## 安全与兼容性

- 收入统计接口继续使用管理员会话认证，不公开收入数据。
- 不修改数据库结构，不删除或重写历史指标。
- 历史别名只参与指标查询与展示，不改变渠道选择、计费或令牌分组绑定。
- 当指定时间窗口确实没有请求样本时，接口仍返回空模型列表。

## 验证计划

- 覆盖收入统计路由注册和聚合查询测试。
- 覆盖当前分组及历史别名的性能摘要查询测试。
- 执行相关 Go 单元测试、前端契约测试和 `git diff --check`。
- 部署 `zzapi` 后验证容器健康、收入接口不再 404，并核对 24 小时、7 天和
  30 天模型摘要中的延迟、吞吐量与状态字段。
