# 官方上游修复选择性回移

日期：2026-08-04

## 目标

以 `QuantumNous/new-api` 官方 `main` 为参考，只回移能够保持本地双前端、结构化分组、
动态计费表达式和扩展能力的小范围修复，不执行整体合并。

本轮重点处理：

- 客户端取消被错误包装为 HTTP 500；
- SSE 已正常收到 `[DONE]` 后被竞态标记为 `client_gone`；
- `.30` 为容量错误重试引入前导帧缓存，造成慢模型首字节饥饿和客户端断流；
- 创建同名模型时可能覆盖或清空既有模型定价；
- 多分组重试是否已经使用最终实际分组完成预消费与结算；
- 其余低冲突的协议、诊断、优雅关闭和适配器修复。

GPT-5.6 的固定模型倍率不在本轮范围。现有自定义补全倍率与动态计费配置继续作为事实来源，
不得因为模型名称匹配而强制覆盖管理员配置。

## 实施原则

1. 先为本地问题建立最小复现测试，再手工移植上游行为。
2. 已有等价实现时只补测试或文档，不重复引入代码。
3. 错误分类必须保留原始 `error` cause，客户端可见消息与内部错误链分离。
4. 模型定价更新必须区分“创建新模型”和“更新同名模型”，不得隐式删除现有倍率、固定价格、
   补全倍率或动态计费表达式。模型重命名到已有定价的目标名称时保留目标定价；只有目标名称
   尚无定价且源价格已实际加载时，才迁移源价格。
5. 计费结算必须使用最终实际请求分组；预消费快照和最终结算不得混用首次候选分组。
6. 所有数据库行为同时兼容 SQLite、MySQL 和 PostgreSQL。

## 安全与兼容边界

- 不修改生产数据库，不重启或部署生产容器。
- 不引入官方前端目录迁移、RelayKit 整体重构、完整认证重构或 ClickHouse 日志体系。
- Codex 上游模型发现只更新渠道模型列表，不能代替模型管理中的元信息和定价。
- 上游错误响应预览必须限制长度并经过现有敏感信息遮罩。
- 优雅关闭默认通过 `SHUTDOWN_TIMEOUT_SECONDS=120` 等待正在处理的请求；只有在后续部署
  同时配置不短于该值的容器停止宽限时间时才完整生效。本次发版不修改生产环境配置，
  也不重启生产容器。

## `.29` 到 `.31` 的流中断回归

版本对应关系：

- `.29`：`31eb14d5f`，尚未引入前导流帧缓存；
- `.30`：`cd36373f1`，为容量错误跨渠道重试增加前导流帧缓存；
- `.31`：`333609168`，只修改运行日志轮转，没有改动 Relay 流处理。

`.30` 会等待首个正文、推理或工具调用后，才把 `role=assistant`、
`response.created` 等前导帧一起下发。生产默认未启用 Ping 时，慢模型在首个正文 token 前
可能长期没有响应字节，客户端或反向代理先关闭连接，服务端随后记录
`request context done: context canceled`。因此 `.31` 表面出现大量 500，但回归源头是
`.30` 的发送策略。

本轮恢复四条 OpenAI 流路径的前导事件立即发送和刷新：原生 Chat Completions、原生
Responses、Responses 转 Chat、Chat 转 Responses。容量错误只有作为第一个上游事件且
下游尚未写入时才能透明重试；一旦任何 SSE 事件已经发送，当前流返回终态错误，不跨渠道
拼接响应。

同时修正普通流内 500 的重试边界：`FirstResponseTime`、`ReceivedResponseCount` 只表示
已经读到上游数据，不能证明响应已经写给客户端。正常 Gin 请求统一以
`Writer.Written()` 为准，因此首个 SSE 错误帧和未下发的非流式 500 可以进入管理员配置的
状态码重试；已经写出生命周期帧、正文或 Ping 后仍禁止在同一连接切换渠道。

亲和命中的渠道发生策略上可重试的失败时，删除对应绑定，使客户端下一次重连不再粘回同一
失败渠道。绑定快照包含渠道、多 Key 索引和唯一修订号；Redis 使用原子比较删除，内存缓存
使用同键锁，避免旧失败请求删除并发请求刚更新的新绑定。失败的 HTTP 200 SSE 不会在
Distributor 返回阶段重新写回亲和缓存。

`NewOpenAIError` 同时保留原始 `context.Canceled` / `context.DeadlineExceeded` cause，
用于消除取消请求被误记为渠道 500；它只修正错误归因，不代替首帧立即发送。
`stream_read_error` 表示上游在已经开始输出后真实断开，仍需按上游渠道单独排查，不应与
本次首字节回归混为一类。

流终态仲裁只允许明确收到 `[DONE]` 覆盖并发出现的 `client_gone` 或 `timeout`。清理阶段的
`EOF`、`handler_stop` 不得覆盖 `scanner_error`、Ping 失败或超时，否则真实上游断开会被
误报为正常结束。

## 测试计划

- `NewOpenAIError` 对 `context.Canceled` 和 `context.DeadlineExceeded` 保持 `errors.Is` 可识别。
- 正常 `[DONE]` 与客户端 Context 几乎同时结束时，正常终态优先于 `client_gone`。
- 真实扫描错误和超时不会被清理阶段的 `EOF` 或 `handler_stop` 覆盖。
- 四条 OpenAI 流路径在第二个上游事件到达前已经写出并刷新首个生命周期或角色事件。
- 容量错误作为首个事件时仍可重试；首帧已发送后则在当前 SSE 返回终态错误。
- 首个普通 SSE 500 已计入接收次数但尚未写出时，仍按状态码跨渠道重试。
- 已提交失败只淘汰实际命中的同一亲和绑定，取消、指定渠道和不可重试错误保持原绑定。
- 创建同名模型不会删除已有输入倍率、输出倍率、固定价格和动态计费表达式；重命名到已有定价
  的目标名称不会用源模型价格覆盖目标价格；目标检测同时覆盖固定价单位、固定价变体、
  缓存创建倍率与动态计费映射。
- 显式多分组和 `auto` 跨组重试成功后，预消费、结算、日志都使用最终实际分组。
- 对每个回移提交执行聚焦测试，并在 60 秒超时内拆分运行 Go 包测试。
- 执行 `go vet`、格式化和 `git diff --check`。

## 回滚

本轮不包含数据库结构迁移。各修复按独立文件和测试拆分，可单独回滚；模型定价保护回滚后，
同名模型创建流程可能再次覆盖管理员定价，因此回滚前应先确认调用方行为。
