# 运行日志存储与轮转优化

## 变更目标

解决 Gin 访问日志不参与旧的显式日志计数，导致 `oneapi-*.log` 单文件在高流量场景下持续增长的问题，同时保留必要的运行审计能力。

## 变更范围

- `logger/`：统一通过轮转写入器保存访问日志、系统日志和错误日志。
- `middleware/logger.go`：支持跳过低价值、高频访问路径。
- `.env.example`、`docker-compose.yml`：补充日志轮转和保留配置。

请求数据库日志、请求归档对象和安全审计事件的存储协议不变。

## 日志边界

- 后台“使用日志”来自数据库 `logs` 表，用于计费、请求查询和用量统计；运行日志轮转与保留配置不会删除这些记录。
- `ERROR_LOG_ENABLED` 只控制普通同步请求的错误记录是否写入数据库使用日志，不控制 `oneapi-*.log` 文件。
- `oneapi-*.log` 是 Gin 访问日志和应用运行日志，仅用于短期排障。
- `RUNTIME_LOG_ENABLED=false` 时，Gin 访问日志和普通信息日志写入 `io.Discard`，不会新建或继续写入 `oneapi-*.log`；错误、警告和致命启动信息仍写入 `stderr`，数据库使用日志不受影响。
- 成功请求原先会把完整计费参数以 `INFO` 再写入磁盘运行日志；现在只在 `DEBUG=true` 时输出，数据库使用日志仍照常写入。

## 配置契约

- `LOG_MAX_SIZE_MB`：单个 `oneapi-*.log` 文件的最大容量，默认 `100`。设置为 `0` 时不按容量轮转，但仍按自然日轮转。
- `RUNTIME_LOG_ENABLED`：常规运行日志开关，默认 `true`。生产环境设为 `false` 可关闭访问日志、普通信息日志和本地日志文件，但始终保留 `stderr` 错误与致命信息。
- `LOG_RETENTION_DAYS`：磁盘运行日志保留天数，程序默认 `0`，表示禁用自动清理。Compose 生产示例设置为 `3`；设置为正整数后，只会清理超过保留期的非活动 `oneapi-*.log` 文件。
- `GIN_LOG_SKIP_PATHS`：逗号分隔的精确路径列表，默认 `/api/status`。设置为 `none` 时不跳过任何路径。

## 轮转行为

1. 服务启动时创建新的 `oneapi-<时间>.log`。
2. 写入后若下一条日志将超过容量上限，则先创建新文件再写入。
3. 跨自然日后的第一条日志会创建新文件。
4. 同一秒发生多次轮转时追加数字后缀，避免覆盖已有文件。
5. 当前活动文件路径继续通过 `logger.GetCurrentLogPath()` 提供，后台日志清理接口不会删除活动文件。

## 安全与兼容性

- 默认不自动删除历史日志；启用 `LOG_RETENTION_DAYS` 前应确认审计和合规保留周期。
- Compose 将 Docker `json-file` 标准输出限制为单文件 `20MB`、最多 `3` 个文件，防止运行日志在宿主机重复无限积累。默认关闭常规运行日志后，Docker 日志仍保留错误与致命启动信息。
- 本地发布目录 `.release-*/` 和请求数据导出目录 `exports/` 均被 Git 忽略；前者可重新构建，后者可能包含敏感请求数据，不得进入提交。
- 自动清理仅匹配日志目录中的 `oneapi-*.log`，不会处理请求归档对象、数据库日志或其他文件。
- `/api/status` 的访问日志默认跳过，但接口响应、健康检查行为和异常日志不受影响。
- 文件命名仍以 `oneapi-` 开头并以 `.log` 结尾，兼容现有后台日志管理页面。

## 测试计划

- 单文件达到容量上限后创建第二个日志文件。
- 启用保留天数后删除过期文件，并保留当前活动文件。
- 跨自然日后的第一条日志创建新文件。
- 关闭常规运行日志后仍保留 `stderr` 错误与致命信息。
- 验证默认和自定义的 Gin 跳过路径。
- 执行 `go test ./logger ./middleware`、`gofmt` 和 `git diff --check`。

## 已知限制

- 本变更不压缩历史日志，也不会迁移或删除升级前已经存在的大文件。
- 多实例部署时每个实例应使用独立日志目录，或改用外部日志采集系统统一管理。
