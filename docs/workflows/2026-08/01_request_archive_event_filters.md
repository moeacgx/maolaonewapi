# 请求归档按审计事件来源、渠道和分组筛选

## 目标与范围

完整请求归档在 `audit_events`（仅归档产生审计事件的请求）范围内新增三个可选筛选
维度，用于减少无关原始请求并支持后续数据清洗：

- `event_sources`：审计来源，可选 Prompt Guard、屏蔽词和上游官方风控；
- `event_channel_ids`：事件发生时固化的最终实际渠道 ID；
- `event_group_codes`：事件发生时固化的最终实际业务分组稳定编码。

空数组表示该维度不限制。同一维度内按“任一匹配”，多个非空维度之间按“同时
满足”组合。例如来源只选择 `upstream_policy`，且选择渠道 306、314 时，仅这两个
渠道产生的官方风控事件会触发原始请求归档。

筛选不作用于 `all_requests`。该范围在渠道分配和审计事件产生前归档，无法可靠取得
最终渠道、最终业务分组或事件来源；管理页面在该范围下禁用三个筛选器，但保留已选值，
切回事件范围后继续生效。

## 数据与接口契约

`request_archive_configs` 新增三个跨数据库普通 `TEXT` 字段，内容均为 JSON 数组，
逻辑默认值为 `[]`：

- `event_channel_ids`：排序、去重后的正整数；
- `event_group_codes`：规范化、排序、去重后的稳定分组编码；
- `event_sources`：排序、去重后的稳定来源，只允许 `prompt_guard`、
  `sensitive_word`、`upstream_policy`。

`GET` 与 `PUT /api/security-audit/request-archive/config` 使用同名数组字段。所有 JSON
编解码通过 `common` 包装函数完成。迁移不为 `TEXT` 声明数据库默认值，避免依赖
MySQL 5.7 不支持的 `TEXT DEFAULT`；旧记录缺少字段、字段为空或读取到 `null` 时均按
空数组处理，升级后保持事件范围原有行为。

## 触发语义与安全边界

筛选发生在审计事件成功写入数据库之后、原始请求候选进入归档队列之前。匹配使用事件
自身已经固化的 `source`、`channel_id` 和 `group_code`，不回查当前渠道、分组或令牌
配置，避免配置变化改写历史事实。请求阶段在选渠前被阻断的事件没有实际渠道；配置了
渠道筛选时，这类事件不会匹配。

单个事件不匹配时只跳过该事件，不能清除请求上下文或异步 Guard 任务中的原始候选。
同一请求之后若产生另一个匹配事件，仍可触发归档。只有归档任务成功入队或数据库去重
确认候选已经入队后才清除候选；队列失败继续沿用既有 `dropped` 指标，且不改变客户端
请求结果。

响应阶段事件使用渠道重试结束后的最终实际分组；选渠前的屏蔽词或 Guard 事件只有在
分组 ID 或结构化令牌分组快照能够确认正式编码时才参与分组筛选。旧分组别名只在事件
确定要写库时解析为当前正式编码，普通显示名称不会被猜成编码；多候选、`auto` 或无法确认
的分组保持空编码，因此配置了分组筛选时不会误匹配。

异步 Guard Worker 租约过期且达到最大重试次数时，失败事件仍先与任务终态在同一事务
落库；维护流程随后补齐旧快照的正式分组编码，并复用相同来源、渠道、分组筛选与归档
去重逻辑。重复维护不会生成第二个归档任务。

筛选只决定是否把已存在的内存候选转入归档队列，不扩大正文采集范围，也不把
Authorization、Cookie、URL 查询参数或其他请求头加入归档。Realtime 继续使用帧级
语义，不因连接后续事件回溯此前帧。

## 兼容性、验证与回滚

迁移通过 GORM 添加普通 `TEXT` 列，兼容 SQLite、MySQL 5.7.8+ 和 PostgreSQL 9.6+。
Default 与 Classic 提供一致的多选配置，并保留已经删除或暂时无法加载的渠道、分组选项，
避免一次页面保存静默清掉既有配置。

SQLite 旧库若尚无 `request_archive_jobs.dedupe_key`，不能让 GORM 直接执行带内联
`UNIQUE` 的 `ALTER TABLE ADD COLUMN`。迁移会先增加普通可空列，再由 GORM 创建独立唯一
索引；新库以及 MySQL、PostgreSQL 仍使用原有自动迁移。升级回归测试从缺少该列的
SQLite 表开始，确认列和唯一索引均补齐，重复去重键仍被数据库拒绝。

两套前端的最终路由分组显示同时读取 `group_name`、`group_code` 和 `group_id`，按名称、
稳定编码、ID 的顺序展示；只有稳定编码的合法事件不再被误标为“历史事件未记录”。

回归测试覆盖空筛选兼容旧行为、单来源筛选、渠道和分组分别匹配、三个维度交集、不匹配
事件保留候选、后续匹配事件归档、异步 Guard 正常与租约终态路径、旧分组别名规范化，
以及 `all_requests` 不应用筛选。交付前执行
Go 定向测试、两套前端测试和构建、国际化同步、格式化及 `git diff --check`。

回滚旧应用前应先清空三个筛选数组；新增普通列可以保留，不需要破坏性数据库操作。
