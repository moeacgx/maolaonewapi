# Classic 模型广场新版模板布局迁移

日期：2026-08-22

## 目标

将 `web/src/features/pricing/` 作为唯一视觉和交互基准，完整移植其模型广场
页面层级、筛选分区、工具栏、卡片、表格和详情抽屉到 Classic；Classic 仅保留
自身真实数据源和已有的计费、性能、折扣与批量操作能力。

## 范围

- 页面采用新版的居中标题、模型计数、搜索框、筛选栏和结果区布局，文案、
  折叠顺序、筛选 Chip 和工具栏主层级均以新版实现为准。
- 宽度不小于 `1280px` 时使用粘性筛选侧栏；较窄宽度使用同一筛选内容的右侧抽屉。
- 筛选分组、供应商、标签、计费类型和端点类型均可独立折叠；筛选项继续显示
  数量、供应商图标和分组倍率。
- 卡片、表格和详情抽屉使用新版的图标、价格、元信息、操作和性能摘要层级；
  不额外设计供应商顶边、语义色分区或彩色卡片。
- 加载骨架与实际卡片共用同一响应式网格和信息密度，避免加载完成时布局跳变。
- 工具栏保留 Classic 的充值价格、货币、倍率、Token 单位、批量复制、
  视图切换和计费说明入口；新增能力收纳到不改变新版主工具栏层级的更多操作中，
  移动端也必须提供等价入口。
- 详情抽屉采用新版的紧凑标题、分区和三标签布局；概览、性能和端点内容
  继续使用 Classic 的动态计费、默认规格价、路由规格价、分组倍率和真实性能。
- API 标签以新版的代码示例和鉴权区块为主结构；真实端点只作为示例切换来源，
  不再额外渲染旧版独立端点表，也不引入新版 mock 参数或限流数据。
- 页面严格复用新版的中性配色、边框、阴影、背景光晕和响应式尺寸，不添加
  Classic 专有的颜色主题、卡片装饰或替代布局。

## 数据与行为约束

- 数据仍由 `useModelPricingData` 提供，模型、供应商、分组、价格和性能接口均未改变。
- 筛选计数继续通过 `usePricingFilterCounts` 计算；分组筛选继续调用
  `handleGroupClick`，使列表筛选分组和价格展示分组始终一致。
- 重置筛选同时恢复 `filterGroup` 与 `selectedGroup`，避免列表已重置而
  卡片、表格或计费说明仍使用旧分组倍率。
- 表格列工厂不再在 memo 回调中读取视口 Hook；卡片/表格切换后仍保持稳定的
  Hook 顺序，移动端固定列规则继续由页面当前视口决定。
- 卡片继续使用 Classic 的价格计算、动态计费摘要、折扣标签和
  `performanceMap`，不复制新版模板的 mock 性能、限流、参数或应用排行数据。
- 详情抽屉在固定价模型上同时展示 `model_price_variants` 和
  `model_route_price_variants`，规格规则仍是最终价格，不能与基础价相加。
- `siteDisplayType === 'TOKENS'` 时仍不展示充值价格与货币选择。

## 可访问性与响应式

- 筛选 Chip 使用原生按钮和 `aria-pressed`；分区折叠和“展开更多”使用
  `aria-expanded`，图标操作保留可访问名称和悬浮提示。
- 卡片、筛选项和工具栏在 `320px` 起允许换行或截断，避免横向溢出。
- 移动端将 Classic 专有的充值价格、货币、倍率、Token 单位、批量复制和计费说明
  收纳到“更多操作”；计费说明仅在用户主动打开后显示，不遮挡新版首屏。

## 验证

- 通过浏览器对照新版与 Classic 的 `390px` 和 `1280px` 视口；标题、搜索、
  侧栏、筛选抽屉、工具栏、卡片网格、表格和详情抽屉均按新版结构核验，未出现
  横向溢出或操作重叠。
- 实测供应商筛选、移动端重置、充值价格与 USD/CNY/自定义币种、倍率、Token
  单位、卡片/表格切换、详情概览/性能/API 标签；移动端更多操作可访问所有
  被收纳的 Classic 二开控制。
- 执行 `pnpm exec prettier --check`、目标 JSX 的 `pnpm exec eslint`、
  `pnpm run build` 及 `git diff --check`。

## 兼容性

本次无后端接口、模型 ID、价格计算规则、额度、鉴权或跨项目契约变更。

## 2026-08-23 模型广场白屏回归修复

### 问题与根因

Classic 模板的 `/pricing` 顶栏渲染带图标的自定义导航项时会白屏。顶栏将
`getCustomNavIcon` 的 JSX 返回值当作组件再次以 `<Icon />` 渲染，触发 React
运行时的无效元素类型错误。该问题仅影响页面展示，不涉及模型、价格、性能或
折扣数据链路。

### 修复范围

- `PricingTemplateHeader` 改用 `getCustomNavIconComponent` 获取 Lucide 组件类型，
  保持现有 `<Icon />` 渲染方式。
- 保持 `Navigation` 对 `getCustomNavIcon` 的直接 JSX 渲染不变，避免改变其他
  Classic 导航的颜色和选中态行为。
- 增加顶栏自定义图标回归用例：验证图标查找结果可作为 React 组件渲染，并要求
  模型广场顶栏使用组件查找 API。

### 验证

- 在修复前，新增用例稳定复现顶栏错误；修复后执行
  `bun test src/components/layout/headerbar/__tests__/pricing-template-header.test.jsx` 通过。
- 对修改的 JSX 和测试执行 Classic ESLint、Prettier 校验和 `git diff --check`，均通过。
- Classic 生产构建通过；发布后需在实际自定义导航配置下访问 `/pricing`，确认
  页面、筛选、卡片和详情均正常渲染且控制台无 React 运行时错误。

## 2026-08-23 模板细节对齐

### 修复范围

- 顶栏继续以新版 `PublicHeader` 的固定定位、滚动收缩和移动端层级为准。
