# 单 Key 渠道监控自动恢复

## 问题与目标

渠道监控在“成功时自动启用”达到阈值后，会把自动禁用的单 Key 渠道恢复为启用状态。但旧路径通过通用状态更新函数恢复渠道，只更新数据库状态和能力状态，没有同步重建内存选渠候选池。

启用内存缓存时，自动禁用会把渠道从 `group2model2channels` 中移除；旧恢复路径只更新 `channelsIDM` 中的渠道状态，业务请求仍可能选不到已经恢复的渠道，直到下一轮全量渠道缓存同步。

本次目标只覆盖单 Key 渠道监控自动恢复：一个渠道配置一个上游密钥。多 Key 密钥池恢复不在本次范围内。

## 实现契约

- `service.EnableChannel` 仍是监控恢复入口，但只调用单 Key 恢复函数。
- `model.EnableAutoDisabledSingleKeyChannel` 只在以下条件同时满足时恢复：
  - 渠道存在；
  - 当前状态仍是 `ChannelStatusAutoDisabled`；
  - 渠道不是多 Key；
  - 本轮探测使用的 Key 与数据库当前 Key 完全一致。
- 状态恢复和 `abilities.enabled = true` 在同一个数据库事务内完成。
- 事务提交成功后，如果启用了内存缓存，立即执行 `InitChannelCache()`，把渠道重新加入对应分组和模型的选渠候选池。
- Key 已被管理员替换、渠道已被手动禁用、渠道变为多 Key、或状态已不是自动禁用时，本轮旧探测结果不会恢复渠道。

## 兼容性

不新增数据表、字段或配置。事务与条件更新只使用 GORM 和现有列，保持 SQLite、MySQL、PostgreSQL 兼容。

## 验证

- 新增模型层测试覆盖：单 Key 自动恢复后内存选渠候选池立即可见，且能力状态同步启用。
- 新增模型层测试覆盖：探测后 Key 已被替换时拒绝恢复，渠道状态和能力状态保持禁用。
