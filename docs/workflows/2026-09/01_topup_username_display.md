# 充值账单用户名显示修复

## 目标

修复 Classic 与 Default 管理员充值账单中用户名显示为空的问题，并让管理员账单搜索兑现界面提示的订单号、用户名和用户 ID 查询能力。

## 根因

`TopUp` 只保存 `user_id`，充值列表接口此前直接序列化 `[]*model.TopUp`，没有查询用户表或生成 `username` 字段。Classic 的管理员表格使用 `dataIndex: 'username'`，Default 管理员徽章也读取 `record.username`，因此所有记录都回退为 `-` 或隐藏。

## 修改范围

- 新增管理员专用 `AdminTopUp` 视图，嵌入订单信息并按当前用户 ID 批量补充用户名，不把冗余用户名写入充值订单。
- 管理员列表和搜索接口改用管理员视图；普通用户接口继续返回原始充值订单，保持权限和数据边界。
- 管理员搜索支持订单号、用户名和精确用户 ID，并继续沿用充值搜索的输入清洗和查询上限。
- Classic 与 Default 前端沿用现有 `username` 字段读取逻辑，无需添加重复的前端兜底。

## 兼容性与安全边界

用户名从当前用户表读取，改名后历史账单显示最新用户名；已软删除用户仍可通过管理员视图读取用户名快照来源。查询使用 GORM 子查询和批量查询，兼容 SQLite、MySQL 和 PostgreSQL，不修改数据库结构。只有已通过管理员路由鉴权的接口返回用户名。

## 验证

- 控制器回归测试验证管理员列表返回当前用户名。
- 控制器回归测试验证按用户名搜索能命中充值订单。
- 交付前执行相关 Go 测试、`gofmt`、前端受影响模板的 lint/typecheck（若依赖可用）和 `git diff --check`。
