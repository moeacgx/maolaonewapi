# Classic 计费说明折扣优先展示

## 问题

Classic 模型广场的计费说明同时展开完整单价公式、四步拆解、卡片样例和逐项 token 费用，重复信息过多。用户最关心的“当前折扣从哪里来”被汇率换算和费用估算淹没，理解计费反而更困难。

## 目标

- 计划随 `v1.0.0-rc.10.1.10.310` 发布；本工作只完成仓库发版，
  不自动更新 `zzapi` 或 `maolaoapi` 容器。
- 计费说明统一使用充值价格口径，不在说明弹窗中切换标准价格。
- 首屏直接突出“充值优惠 × 分组倍率 = 综合折扣”，并展示当前模型和分组的实际数字，让用户一眼看到最终折数如何得出。
- 首屏用“官方价 → 实付价”说明折扣结果，不重复展示公式拆解、卡片样例和公式代入。
- 充值汇率、美元汇率、展示货币换算和精确单价代入收进“计算详情”，需要复核时再展开。
- 实际 token 花费估算改为次级入口，不再作为计费说明的强制第二步。
- 保留动态计费档位、移动端布局和现有模型/分组选择能力。

## 计算契约

首屏展示的折扣按以下顺序计算：

```text
充值优惠系数 = 充值汇率 ÷ 美元汇率
综合折扣系数 = 充值优惠系数 × 分组倍率
最终折数 = 综合折扣系数 × 10
```

例如充值汇率为 `1.03`、美元汇率为 `6.71`、分组倍率为 `0.15` 时：

```text
1.03 ÷ 6.71 × 0.15 = 0.023025...
最终折数 = 0.023025... × 10 ≈ 0.23 折
```

“计算详情”继续保留完整充值单价契约：

```text
充值单价
= 官方美元单价
×（充值汇率 ÷ 美元汇率）
× 分组倍率
× 展示货币汇率
```

其中展示货币汇率只负责把美元计价结果换算为当前展示货币，不参与“最终折数”的定义。首屏实际价格与详情使用同一组底层数据，不另设简化算法。

次级入口中的一次请求花费仍按每类 token 分别计算，再求和：

```text
单项费用 = token 数 ÷ 1,000,000 × 对应充值单价
实际扣费 = 输入费用 + 输出费用 + 缓存读取费用 + 缓存创建费用
```

其中 `/M` 表示每 1,000,000 个 token。页面金额显示 6 位小数，详情和费用汇总保留足够精度，避免用户使用展示值复算时出现明显偏差。

## 展示层级

1. 首屏展示模型、分组、最终折数、折扣来源和“官方价 → 实付价”。
2. “计算详情”展示充值汇率除以美元汇率、分组倍率、展示货币汇率和完整单价代入。
3. “实际 token 花费”作为次级入口，继续提供输入、输出、缓存读取和缓存创建的数量与小计。

三层内容共用同一计费结果；交互收敛只改变信息优先级，不改变价格计算或结算行为。

## 实现范围

- `web/classic/src/components/table/model-pricing/billing/BillingGuide.jsx`
  负责折扣优先的首屏、计算详情和实际 token 花费次级入口。
- `web/classic/src/components/table/model-pricing/layout/PricingPage.jsx`
  不再向说明弹窗传入普通价格格式化函数，由弹窗内部统一构造充值价格格式化函数。
- 详情与实际花费入口复用 Classic 现有多语言文案键；新增“充值优惠”键并同步
  `zh-CN`、`zh-TW`、`en`、`fr`、`ru`、`ja`、`vi` 七个语言包。

## 兼容性与边界

- 不改变后端价格字段、模型广场 API、分组倍率或动态计费表达式。
- 不改变充值优惠系数、充值单价、逐类 token 小计或总扣费的底层算法。
- 计费说明仍然是基于模型卡片当前单价的估算；Claude 缓存创建的既有 5m/1h 分档提示继续保留。
- `TOKENS` 展示模式不打开计费说明入口，现有入口可用性规则不变。

- 使用 Prettier 检查修改后的 Classic 文件和开发文档。

- 展开计算详情，核对汇率、分组倍率、展示货币换算和完整单价代入与首屏结果一致。
- 打开实际 token 花费次级入口，核对各类 token 小计、总费用、动态计费档位和返回首屏的交互。
