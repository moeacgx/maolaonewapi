# 计费说明固定充值价格与完整公式

## 问题

Classic 模型广场的计费说明只展示“汇率优惠 × 分组倍率”等摘要，用户需要自行推断 `/M`、充值汇率和每项 token 费用的关系，无法直接复算卡片价格和一次请求的总扣费。

## 目标

- 计划随 `v1.0.0-rc.10.1.10.308` 发布并仅更新 `zzapi`。
- 计费说明统一使用充值价格口径，不在说明弹窗中切换标准价格。
- 先展示完整的充值单价公式，再展示当前模型、分组和展示货币的实际代入值。
- 在实际花费步骤中，为输入、输出、缓存读取和缓存创建分别展示完整等式及精确小计。
- 保留动态计费档位、移动端布局和现有模型/分组选择能力。

## 计算契约

充值价格的单价按以下顺序计算：

```text
充值单价
= 官方美元单价
×（充值汇率 ÷ 美元汇率）
× 分组倍率
× 展示货币汇率
```

一次请求的扣费按每类 token 分别计算，再求和：

```text
单项费用 = token 数 ÷ 1,000,000 × 对应充值单价
实际扣费 = 输入费用 + 输出费用 + 缓存读取费用 + 缓存创建费用
```

其中 `/M` 明确表示每 1,000,000 个 token。页面金额显示 6 位小数，汇总等式保留 9 位小数，避免因显示四舍五入造成用户无法复核。

## 实现范围

- `web/classic/src/components/table/model-pricing/billing/BillingGuide.jsx`
  负责固定充值价格口径、公式拆解、当前示例代入和逐项费用等式。
- `web/classic/src/components/table/model-pricing/layout/PricingPage.jsx`
  不再向说明弹窗传入普通价格格式化函数，由弹窗内部统一构造充值价格格式化函数。
- Classic 多语言资源补充新增说明文案。

## 兼容性与边界

- 不改变后端价格字段、模型广场 API、分组倍率或动态计费表达式。
- 计费说明仍然是基于模型卡片当前单价的估算；Claude 缓存创建的既有 5m/1h 分档提示继续保留。
- `TOKENS` 展示模式不打开计费说明入口，现有入口可用性规则不变。

## 验证计划

- 运行 `node --test web/classic/src/components/table/model-pricing/billing/utils.test.mjs`，确认价格、汇率系数、动态计费和 token 小计工具契约不回归。
- 使用 Prettier 检查修改后的 Classic 文件和多语言 JSON。
- 在浏览器检查桌面与窄屏布局、模型/分组切换、下一步/上一步和充值公式的数值一致性。
